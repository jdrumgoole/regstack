## 🟡 INFO (Best practice recommendations)

### I1 — Per-IP rate limiting default-off *(carry-over)*

**File:** `docs/configuration.md:248–258`, `src/regstack/config/schema.py:224–241`

Per-IP rate limits on `/register`, `/forgot-password`, and `/resend-verification` default to unset. The
documentation explains why (enabling them fails closed for hosts without the `rate_limit` extra / `slowapi`);
per-account lockout on `/login` is always on. Operators should set IP-level limits appropriate to their
traffic profile.

**Recommendation:** Configure `register_rate_limit`, `forgot_password_rate_limit`, and
`resend_verification_rate_limit` in production deployments to protect outbound email budget and
prevent address-harvesting probes.

---

### I2 — `UserPublic.tokens_invalidated_after` exposed in API responses *(carry-over)*

**File:** `src/regstack/models/user.py:105`

`tokens_invalidated_after` appears in `/me`, `/admin/users/{id}`, and every `UserPublic` response.
Documented trade-off: SPAs use it to detect stale sessions. If internal event timing is sensitive,
the field should be excluded from `UserPublic`. No change since last review.

---

### I3 — Admin error messages echo the `email` path parameter *(carry-over)*

**File:** `src/regstack/routers/admin.py:224,229`

Two admin-only endpoints include the email from the URL path in error responses. Safe today because
only superusers reach these endpoints. If the admin guard were ever accidentally removed, these
messages would leak whether an address exists — contradicting the anti-enumeration discipline on
`/forgot-password` and `/resend-verification`. No change since last review.

---

### I4 — `oauth` extra explicitly pins `cryptography>=48.0.1` *(carry-over)*

**File:** `pyproject.toml:98`

The `oauth` extra carries an explicit `cryptography>=48.0.1` floor alongside `pyjwt[crypto]>=2.13.0`
because `pyjwt[crypto]` transitively pulls `cryptography` without a floor high enough to close
CVE-2026-45447 (CVSS 9.8 Critical — heap use-after-free in OpenSSL `PKCS7_verify()`, first clean
release 48.0.1). The explicit pin is correct defence-in-depth. No change since last review.

---

### I5 — SNS SMS backend uses boto3 default credential chain *(carry-over)*

**File:** `src/regstack/sms/sns.py:29`

`aioboto3.Session()` is constructed with no credential arguments and relies on the ambient boto3
credential chain (instance profile, env vars, etc.). Asymmetric with the SES email backend which
exposes explicit `ses_access_key_id` / `ses_secret_access_key` config fields. Noted for operator
awareness. No change since last review.

---

### I6 — OAuth exchange consumes expired state before returning 400 *(carry-over)*

**File:** `src/regstack/routers/oauth.py:151–161`

`/oauth/exchange` atomically consumes (deletes) the state row and then checks `state.expires_at
< rs.clock.now()`. An expired row is permanently consumed before the 400 is returned, forcing the
user to restart the OAuth flow. The ordering is secure (no replay possible after delete), but
check-before-consume would be friendlier. No change since last review.

---

### I7 — `cmd:` log-source kind executes operator-supplied shell commands *(carry-over)*

**File:** `src/regstack/cli/validate/logtail.py:106`

The `cmd:<shell>` log-source kind runs `sh -c <target>` where `<target>` is the operator's
configured value. This is the documented contract for this source kind — intentional operator-level
behaviour, not user input, and not reachable through the HTTP API. Noted for auditors. No change
since last review.

---

### I8 — `SecantusDB>=0.6.0b2` is a pre-release dependency in the `secantus` extra *(carry-over)*

**File:** `pyproject.toml:94`; `uv.lock` (locked at `secantusdb==0.6.0b3`)

The `secantus` extra (`pip install regstack[secantus]`) pulls in `SecantusDB>=0.6.0b2`. The `uv.lock`
still pins `0.6.0b3`; the previous review noted `0.6.0b4` was available. No CVEs have been found
against any SecantusDB release. No change since last review.

**Recommendation:** Run `uv lock` to pull in the latest beta release. Once SecantusDB ships a stable
`1.0.0`, tighten the floor from `>=0.6.0b2` to `>=1.0.0`.

**§14 — OAuth subsystem:** `code_verifier` stored on the state row (DB column); only

`rs.clock.now()` for expiry (not `datetime.now(UTC)`). `/oauth/exchange` atomically consumes the
row (delete) before checking expiry (see I6 for ordering note). ID-token verification validates

pyjwt exceptions with a generic outer message; specific failure text logged at WARNING, never
echoed to the redirect. Linking policy: `email_in_use` for existing email-only accounts unless
`oauth.auto_link_verified_emails=True` AND `email_verified=true`; `identity_in_use` and

correct 400 on `change-password` / `change-email` / `delete-account`; `DELETE /oauth/{provider}/link`
returns 400 when the provider is the only sign-in method. `(provider, subject_id)` and
`(user_id, provider)` uniqueness enforced at DB level (Mongo unique indexes via `install_indexes`,
SQL `UniqueConstraint`). OAuth hooks fire at the four documented event names (`oauth_signin_started`,
`oauth_signin_completed`, `oauth_account_linked`, `oauth_account_unlinked`). `_validate_redirect`
rejects backslash, protocol-relative `//`, and off-origin full URLs.
