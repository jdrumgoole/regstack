### W-3 — CVE-2026-45447: `cryptography` bundled OpenSSL heap UAF (CVSS 7.5 High) — carry-forward (day 10)

**Package:** `cryptography` (in `oauth` optional extra: `cryptography>=46.0.7`)
**Resolved (lock):** `47.0.0` · **Safe version:** `>=48.0.1`
**Advisory:** GHSA-537c-gmf6-5ccf · Published: June 9, 2026
**Tracked:** GitHub issue #123

All PyPI `cryptography` wheels `>=0.5.0,<48.0.1` include a statically-linked OpenSSL
version with a heap use-after-free in `PKCS7_verify()` (empty `digestAlgorithms` SET
in a PKCS#7/S/MIME message). Regstack's `PyJWKClient` path uses RSA/EC key operations
and does not call `PKCS7_verify()` directly, but the `oauth` extra floor `>=46.0.7`
allows consumers to resolve `47.0.0` (vulnerable).

**Action required:**
1. Bump `oauth` extra: `"cryptography>=48.0.1"` with updated CVE comment in
   `pyproject.toml`.
2. Bump `dev` extra: `"cryptography>=48.0.1"`.
3. Run `uv lock`.

### W-4 — CVE-2026-53533: `aiosmtplib 5.1.0` SMTP command injection (CVSS 6.5 Moderate) — carry-forward (day 9)

**Package:** `aiosmtplib` (base dependency: `aiosmtplib>=3.0`)
**Resolved (lock):** `5.1.0` · **Safe version:** `>=5.1.1`
**Advisory:** GHSA-v3q9-hj7j-63hq · Published: June 15, 2026
**Tracked:** GitHub issue #124

The locked version (`5.1.0`) is the vulnerable version. `5.1.1` rejects C0 control
characters (CR, LF, NUL, etc.) in SMTP command arguments. Prior versions accept them,
allowing SMTP injection via a crafted email address such as
`attacker@evil.com\r\nBcc: victim@example.com`, which can silently add blind-copy
recipients to verification, password-reset, or MFA emails. This is directly on
regstack's security-critical email delivery paths.

**Action required:**
1. Bump `"aiosmtplib>=5.1.1"` in `pyproject.toml` with updated CVE comment.
2. Run `uv lock`.

### W-5 — CVE-2026-32690: `pydantic-settings 2.14.0` symlink path traversal (CVSS 5.9 Medium) — carry-forward (day 9)

**Package:** `pydantic-settings` (base dependency: `pydantic-settings>=2.2`)
**Resolved (lock):** `2.14.0` · **Safe version:** `>=2.14.2`
**Advisory:** DailyCVE DC-Jun2026-536 · Published: June 2026
**Tracked:** GitHub issue #125

The locked version (`2.14.0`) is in the vulnerable range (`2.12.0`–`2.14.1`). When a
`BaseSettings` subclass reads from a secrets directory, the size-check does not follow
symlinks but the file-loader does. An attacker with write access to the secrets
directory can create a symlink to an arbitrary filesystem path; `pydantic-settings`
reads the target file and exposes it as a config value. `RegStackConfig` extends
`BaseSettings` and reads from `secrets_env_path` (`regstack.secrets.env`).

**Action required:**
1. Bump `"pydantic-settings>=2.14.2"` in `pyproject.toml`.
2. Run `uv lock`.

## 🟡 INFO (Best practice recommendations)

### I-1 — `UserPublic.tokens_invalidated_after` and `phone_number` exposure (carry-forward)

`UserPublic` exposes `tokens_invalidated_after` (intentional — allows SPA clients to
detect bulk-revocation without an extra round-trip) and `phone_number` (design
decision). Hosts with stricter PII requirements should subclass `UserPublic` or add a
projection step. No code change required in regstack itself; documented here for host
awareness.

### I-2 — `admin_promote_pending` path parameter not validated as `EmailStr` (carry-forward)

`POST /admin/pending/{email}/promote` (`src/regstack/routers/admin.py:204`) accepts
`email: str = Path(...)`. A syntactically invalid email address passes parameter
binding and returns a 404 (LookupError path). The endpoint is admin-gated so the risk
is low. Fix is a one-liner: `email: Annotated[EmailStr, Path(...)]`.
