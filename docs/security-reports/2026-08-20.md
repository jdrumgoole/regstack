## 🟠 WARNING

### W-1 (carry-over, day 10 — DEADLINE MISSED 2026-08-18)

**Section:** §1 — Dependency Vulnerability Check
**CVE:** CVE-2026-69247 — `pkcs7_decrypt` Bleichenbacher oracle
**Affected:** `cryptography` ≥ 44.0.0, < 50.0.0
**Fix:** Bump floor to `cryptography>=50.0.0` in `oauth` and `dev` extras in `pyproject.toml`; run `uv lock`
**Tracking:** GitHub issue #181 (`[security] Raise cryptography floor to >=50.0.0`), open since 2026-08-19

`pyproject.toml` HEAD (`b3aacf9`) still declares:
```toml
oauth = ["pyjwt[crypto]>=2.13.0", "cryptography>=48.0.1", "httpx>=0.27"]
...
"cryptography>=48.0.1",   # in dev extra
```

As of `uv.lock`, the resolved version is 49.0.0 — within the affected range (≥44.0.0, <50.0.0).

**Technical impact:** `pkcs7_decrypt_der`, `pkcs7_decrypt_pem`, and `pkcs7_decrypt_smime` exposed distinguishable error paths and timing differences during RSA `RecipientInfo.encryptedKey` decryption, constituting a Bleichenbacher oracle. An attacker submitting adaptive chosen ciphertext to a service reflecting the outcome can recover the RSA content-encryption key. regstack itself does not call PKCS#7 decrypt, but `pip install regstack[oauth]` resolves to 49.0.0 by default, shipping a version with an open advisory to all consumers.

**Required action:** One-line `pyproject.toml` change + `uv lock` + add CVE-2026-69247 to the comment block alongside the existing cryptography CVE annotations.
