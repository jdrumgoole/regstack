### §3 — Authentication & Authorization Audit

✅ Clean

**Mounted routers:** All routers are conditionally mounted through
`build_router(rs)` in `routers/__init__.py` using the appropriate config
flags (`enable_admin_router`, `enable_ui_router`, `enable_sms_2fa`,
`enable_oauth`). Every authenticated endpoint injects either
`rs.deps.current_user()` or `rs.deps.current_admin()`.

**Bulk-revoke discipline:**
- Password reset (`POST /reset-password`): calls `users.update_password()`,
  which bumps `tokens_invalidated_after` at the repo level. ✅
- Password change (`POST /change-password`): calls `users.update_password()`. ✅
- Email-change confirm (`POST /confirm-email-change`): calls
  `users.update_email()`, which bumps `tokens_invalidated_after`. ✅
- Admin disable (`PATCH /admin/users/{id}` with `is_active=False`): calls
  `users.set_active()` **and** explicitly calls
  `users.set_tokens_invalidated_after(user.id, rs.clock.now())`. ✅
- Account deletion (`DELETE /account`): calls
  `rs.oauth_identities.delete_by_user_id(user.id)` before
  `rs.users.delete(user.id)` — no orphan identity rows. ✅

**OAuth-only user (`hashed_password=None`) handling:**
- `POST /login` (login.py:99): `if user.hashed_password is None or not
  rs.password_hasher.verify(...)` — returns the same generic 401 as a
  wrong-password attempt. No enumeration of OAuth-only accounts. ✅
- `require_password_set` helper (routers/_helpers.py:21) raises 400
  with a forgot-password pointer for `change-password`, `change-email`,
  `delete-account`. ✅
- `DELETE /oauth/{provider}/link` checks `has_password` and linked
  identity count before allowing unlink. ✅

**Constant-time comparison:** password verification delegates to
`pwdlib.PasswordHasher.verify()` (Argon2), which uses a constant-time
comparison internally. No `==` comparisons of passwords anywhere in the
routers. ✅

**Per-purpose JWT keys:** `JwtCodec._key(purpose)` calls
`derive_secret(master, purpose)` (HMAC-SHA256) — confirmed in
`src/regstack/auth/jwt.py` and `src/regstack/config/secrets.py`. ✅

### §4 — Storage-layer Injection Safety

✅ Clean

**MongoDB backend:** Grep of `src/regstack/backends/mongo/` for
`$where`, `$expr`, `$function`, `$accumulator` returned no results. All
query filters are built from typed Python dicts using literal keys and
values from Pydantic-validated models. `ObjectId` parsing in every
repository uses `ObjectId.is_valid(user_id)` guard before calling
`ObjectId(user_id)`, preventing `bson.errors.InvalidId` from propagating
as a 500. No regex patterns built from user input.

**SQL backend:** All queries in `src/regstack/backends/sql/` use
SQLAlchemy Core with parameterized binds (no f-string or `%` interpolation).
Two `text()` calls exist:
1. `text("SELECT 1")` in `backend.py:75` — health-check ping, no user input.
2. `sa.text("SELECT COUNT(*) FROM users WHERE hashed_password IS NULL")` in
   migration `0002_oauth.py:93` — a migration pre-check, no user input.

Neither is an injection surface.

**UtcDateTime TypeDecorator** (`src/regstack/backends/sql/types.py`):
`process_result_value` attaches UTC tzinfo unconditionally when the driver
returns a naive datetime, preventing tz-mismatch `TypeError` in bulk-revoke
comparisons. ✅

**purge_expired() implementations:** All SQL repos implement `purge_expired()`
using SQLAlchemy ORM `delete()` with a column-comparison bound parameter —
no raw SQL interpolation. ✅

### §5 — Input Validation & Injection

✅ Clean

All API endpoints accept typed Pydantic request models (`ConfigDict(extra="forbid")`
on sensitive ones like `ExchangeRequest`). No endpoint accepts a raw `dict`
or untyped JSON body.

Email fields use `pydantic.EmailStr` (backed by `email-validator`). Phone
fields go through `is_valid_e164()` before storage (confirmed in
`src/regstack/routers/phone.py`).

Email template rendering uses `jinja2.Environment` with
`autoescape=select_autoescape(["html"])` — confirmed in
`src/regstack/email/composer.py:60`. HTML email templates escape by default;
plain-text variants are not auto-escaped (correct: they carry no HTML).

SSR templates (`src/regstack/ui/templates/`): grep for `| safe`,
`autoescape false`, and `Markup(` returned no results. ✅

The `_validate_redirect()` function in `src/regstack/routers/oauth.py:515`
validates `redirect_to` against `config.base_url` using `urlsplit`. It
also rejects bare `\\` characters (Windows path bypass) and `//`-prefixed
paths (protocol-relative URLs). Non-absolute paths must start with `/` and
not `//`. Same-origin full URLs are compared scheme+host against
`config.base_url`. ✅

CLI wizards (`regstack init`, `regstack oauth setup`) write TOML and do not
pass any user input to a shell command. ✅

### §6 — Rate Limiting & DoS Prevention

✅ Clean

**Login lockout order:** `rs.lockout.check(payload.email)` (line 73 of
`login.py`) executes **before** user lookup and password verification. A
locked-out account returns 429 with `Retry-After` regardless of whether the
submitted password is correct — no oracle for correct-password-but-locked. ✅

**MongoDB TTL:** `login_attempts` has a `when_ttl` index with
`expireAfterSeconds=config.login_lockout_window_seconds`. ✅

**SQL lockout:** `SqlLoginAttemptRepo` filters by `when >= cutoff` on read
and exposes `purge_expired()` for host-scheduled cleanup. Documented
pattern. ✅

**Admin pagination:** `GET /admin/users` accepts `limit` as
`Annotated[int, Query(ge=1, le=200)]` — hard cap at 200. ✅

**OAuth state TTL:** `oauth_states` has `oauth_state_ttl` index
(`expireAfterSeconds=0` on `expires_at`) on Mongo. SQL backend exposes
`purge_expired()`. ✅

**File uploads:** No user-facing file upload endpoints exist. ✅

### §7 — Session & Token Security

✅ Clean

**JWT configuration:** HS256 algorithm confirmed. `JwtCodec.__init__` enforces
`len(raw) >= MIN_JWT_SECRET_LENGTH` (32 chars) — raises `ValueError` on
shorter secrets. ✅

**Float `iat`:** `TokenPayload.to_claims()` emits `"iat": self.iat.timestamp()`
— Python `.timestamp()` returns a float. ✅ The bulk-revoke comparison
`payload.iat <= cutoff` is therefore sub-second precise.

**pyjwt exp/iat disabled:** `JwtCodec.decode` sets `options={"verify_exp":
False, "verify_iat": False, "verify_nbf": False}` and re-validates both
against the injected `Clock`. ✅ `FrozenClock`-driven tests work correctly.

**Required claims:** `options={"require": ["sub", "exp", "iat", "jti",
"purpose"]}` — every token must carry `jti` for per-token revocation. ✅

**`_authenticate` chain** (verified in `src/regstack/auth/dependencies.py`):
1. Decode token — 401 on `TokenError`; error detail is a static
   `"Invalid or expired token."` that never echoes pyjwt internals. ✅
2. `blacklist.is_revoked(payload.jti)` — 401 if revoked. ✅
3. `users.get_by_id(payload.sub)` + `user.is_active` check — 401 if not
   found or inactive. ✅
4. `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` — 401 if
   `iat <= cutoff`. ✅

**Token logging:** Grep for log statements near `token`, `secret`, `password`
in `src/` returned only two warning lines in `routers/oauth.py` that log
the `OAuthTokenExchangeError` / `OAuthIdTokenError` exception message. These
are generic wrapper messages (`"google token exchange failed: HTTP 400"`,
`"id token verification failed: Signature verification failed"`) — internal
server-side diagnostics, never returned to the client. No JWT body, no raw
tokens, no secrets appear in log output. ✅

### §11 — Third-Party Integration Security

✅ Clean

**SMTP backend:** `EmailConfig.smtp_password` is `SecretStr | None`. The
`aiosmtplib` backend extracts it via `.get_secret_value()` only at send
time. No logging of the password. ✅

**SES backend:** AWS credentials (`ses_access_key_id`,
`ses_secret_access_key`) are `SecretStr | None` in config. The SES backend
performs a lazy `aioboto3` import, so a base install with no `ses` extra
does not pull `aioboto3`. Credentials come from config only (no hardcoded
values). ✅

**SNS / Twilio SMS:** Same pattern — `SecretStr` fields in config, lazy
imports, credentials from config only. ✅

**Google OAuth ID-token verification:**
- `PyJWKClient` initialised with `cache_keys=True, timeout=JWKS_FETCH_TIMEOUT_SECONDS` (5s).
- JWKS fetch offloaded to `asyncio.to_thread()` so a slow Google endpoint
  does not pin the event loop. ✅
- `pyjwt.decode` validates: RS256 signature via JWKS key, `iss` against
  configured issuer (default `https://accounts.google.com`), `aud` against
  `client_id`, `exp`, `iat`, and `nonce`. Required claims enforced via
  `options={"require": ["sub", "iss", "aud", "exp", "iat", "nonce"]}`. ✅
- Any verification failure raises `OAuthIdTokenError` with a generic outer
  message; specific pyjwt reason is logged to server at WARNING level only,
  never echoed to the redirect. ✅

### §14 — OAuth Subsystem Audit

✅ Clean

**14a — PKCE invariants:** `_begin_flow()` generates a `code_verifier`
server-side and stores it on the `oauth_states` row. The `authorization_url()`
call receives only `code_challenge` (SHA-256 of the verifier, base64url
encoded). The raw verifier is never embedded in the redirect URL the browser
sees. ✅

**14b — State row lifecycle:**
- Missing row → `state.consume()` returns `None` → 404 response. ✅
- Expired row → explicit `state.expires_at < rs.clock.now()` check (uses
  injected clock, not `datetime.now(UTC)`). ✅
- `oauth_states.consume(id)` is an atomic read-then-delete (find-and-delete
  semantics) — a second exchange with the same `id` returns `None` → 404. ✅

**14c — ID-token verification:** Confirmed in `GoogleProvider.verify_id_token`:
signature via JWKS, `iss` matches configured issuer, `aud` matches
`client_id`, `exp` and `iat` validated by pyjwt (these are correctly left to
pyjwt here, as opposed to session tokens where the injected clock matters),
`nonce` compared after decode. Any failure → `OAuthIdTokenError` with generic
outer message; specific reason logged at WARNING server-side only. ✅

**14d — Linking-policy enforcement:** Verified in OAuth callback:
- Existing email account + no auto-link → `?error=email_in_use`. ✅
- Identity already linked to a different user → `OAuthIdentityAlreadyLinkedError`
  caught → `?error=identity_in_use`. ✅
- Re-linking same identity to same user → `?error=already_linked`. ✅
- `auto_link_verified_emails=True` gates on `email_verified` claim from ID token. ✅

**14e — OAuth-only user side effects:**
- `POST /login` returns same 401 for `hashed_password=None` users. ✅
- `POST /change-password`, `POST /change-email`, `DELETE /account`: guarded
  by `require_password_set()` helper → 400 with forgot-password pointer. ✅
- `DELETE /oauth/{provider}/link`: checks `has_password` and linked identity
  count; returns 400 (`"Cannot unlink your only sign-in method."`) when
  user has no password and only one provider. ✅

**14f — Identity uniqueness:** Mongo: `provider_subject_unique` and
`user_provider_unique` indexes in `install_indexes()`. SQL: `UniqueConstraint
("provider", "subject_id", name="provider_subject_unique")` and
`UniqueConstraint("user_id", "provider", name="user_provider_unique")` in
`schema.py`. Both backends enforce at DB level. ✅

**14g — Hooks:** `oauth_signin_started`, `oauth_signin_completed`,
`oauth_account_linked`, `oauth_account_unlinked` all present in
`KNOWN_EVENTS` (`src/regstack/hooks/events.py`). Router fires them at the
correct transition points. ✅
