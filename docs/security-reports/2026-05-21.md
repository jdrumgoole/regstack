## 🟡 INFO (Best practice recommendations)

### I-1 · `tokens_invalidated_after` exposed in `UserPublic` API responses (carry-forward)

**Location:** `src/regstack/models/user.py:105`

`UserPublic` includes `tokens_invalidated_after`, the bulk-revoke cutoff timestamp. The
field is intentionally included (documented in `docs/security.md`) so SPA clients can
compare it against their session JWT `iat` to detect invalidated sessions without extra
round-trips. The trade-off was accepted and documented in the 2026-05-17 review (I-2).

No code change required. Carried forward for ongoing awareness: the field discloses
the timestamp of the most recent credential-changing event, which a persistent attacker
could use for correlation. Hosts that want to hide it can wrap `UserPublic` in their own
response model and exclude the field.

---

### I-2 · `UserPublic.phone_number` returned to all authenticated callers including admin listing

**Location:** `src/regstack/models/user.py:100`, `src/regstack/routers/admin.py:73`

The admin `GET /admin/users` endpoint returns a list of `UserPublic` objects. Each includes
`phone_number` in plaintext. For deployments where MFA phone numbers are considered PII
that operators should not be able to bulk-export (GDPR/CCPA contexts), this may warrant
a masked projection (e.g., returning only the last four digits). The `/me` endpoint
returning one's own phone number is appropriate; bulk admin export is a higher-risk
surface.

**Recommendation:** Consider a separate `AdminUserPublic` projection that masks
`phone_number` or omits it, or document the exposure explicitly so host operators can
make an informed decision. The current `limit=200` cap on admin pagination
(`src/regstack/routers/admin.py:69`) reduces bulk-export throughput but does not
prevent it.

Risk is **low-info** — no secret value is leaked, but phone number is regulated PII
in many jurisdictions.

### I-3 · MongoDB server CVE-2025-14847 (MongoBleed) — operator advisory (carry-forward)

**Affected component:** MongoDB server binary (not the pymongo driver)  
**CVSS:** 8.7

CVE-2025-14847 ("MongoBleed") allows an unauthenticated network attacker to leak server
memory via crafted zlib-compressed messages. Affects MongoDB ≤ 8.2.2, ≤ 8.0.16, ≤ 7.0.27,
≤ 6.0.26, ≤ 5.0.31, ≤ 4.4.29. The pymongo driver is not the vulnerable component.

`regstack doctor` (commit `ad23869`) now checks the connected MongoDB server version
against the CVE-2025-14847 baseline and emits a WARNING when the server is below the
patched floor. **The code-level mitigation is in place.** Carrying forward as an operator
advisory: host operators running the mongo backend should ensure MongoDB Server is at
≥ 8.2.3 / 8.0.17 / 7.0.28 / 6.0.27 / 5.0.32 / 4.4.30.

### §6 Rate Limiting & DoS Prevention

**Per-account login lockout:** `LockoutService` records failures per email address;
`lockout.check()` is called at the top of `POST /login` before any authentication work.
Locked accounts return HTTP 429 with `Retry-After`. ✓

**Rate-limit bypass in tests:** `rate_limit_disabled=True` short-circuits all lockout
writes and checks (`auth/lockout.py:86,104,117`). This flag is intended for the test
suite and is `False` by default. Hosts should ensure this flag is never set in
production via environment variable or config. ✓

**Optional per-route slowapi limits:** Hosts that install `regstack[rate_limit]` and
configure `*_rate_limit` strings get IP-level rate limiting on individual routes. If
limits are configured but `slowapi` is not installed, the constructor raises
`RuntimeError` (fails closed). ✓

**DoS via multipart:** `python-multipart>=0.0.27` is enforced in `pyproject.toml` to
pick up CVE-2026-40347 (oversized preamble) and CVE-2026-42561 (unbounded header
count). ✓

**Finding:** No new DoS surface identified.

### §7 Session & Token Security

**JWT algorithm:** Locked to HS256/HS384/HS512 via `JwtAlgorithm` Literal
(`config/schema.py:19`). No asymmetric or `none` algorithm allowed. ✓

**Algorithm confusion:** `pyjwt.decode()` passes `algorithms=[self._config.jwt_algorithm]`
— a list, not `None`. PyJWT will reject tokens signed with any other algorithm. ✓

**Per-purpose key derivation:** `derive_secret(master, purpose)` uses HMAC-SHA256.
Each of the five purposes (session, password_reset, email_change, phone_setup, login_mfa)
signs with a distinct derived key. ✓

**Blacklist TTL:** The SQL `blacklist` table's `exp` column is indexed
(`ix_blacklist_exp`); the Mongo `token_blacklist` collection carries a TTL index with
`expireAfterSeconds=0`. Revoked tokens are reaped automatically after their `exp`. ✓

**Float `iat`:** `iat` is emitted as `now.timestamp()` (float) not `int(...)`, so the
bulk-revoke `iat <= cutoff` comparison is sub-second precise. ✓

**MFA pending token TTL:** Configurable via `mfa_pending_token_ttl_seconds` (default
short); stored in the state row with a shortened expiry after callback completion
(`routers/oauth.py:376`). ✓

**Password-reset token one-time use:** Consumed `jti` is added to the blacklist on
successful reset (`routers/password.py:117`), preventing link reuse. ✓

**Finding:** No session or token security issues found.

### §14 OAuth Subsystem Audit

**Provider registry:** `OAuthRegistry` is populated only when `enable_oauth=True` and
both `google_client_id` and `google_client_secret` are set. Empty registry = no OAuth
routes mounted. ✓

**PKCE implementation (`_begin_flow`):**
- `code_verifier = secrets.token_urlsafe(64)` — 384 bits of entropy. ✓
- `code_challenge = base64.urlsafe_b64encode(sha256(verifier)).rstrip(b"=")` — S256
  method as required by RFC 7636. ✓
- `nonce = secrets.token_urlsafe(16)` — 96 bits; included in the authorization URL
  and validated against the ID token claim. ✓
- `state_id = secrets.token_urlsafe(32)` — 192 bits. ✓

**State row lifecycle:**
- State rows carry `expires_at`; expired rows are rejected in both `oauth_start` and
  `oauth_callback`. ✓
- `oauth_states.consume()` deletes the row atomically on `POST /oauth/exchange`,
  making state IDs single-use. ✓
- After callback, the state row's expiry is shortened to `completion_ttl_seconds`
  (default 30 s), minimising the window between callback and exchange. ✓

**Redirect validation (`_validate_redirect`):**
- Rejects backslash in the raw string (browser normalises `\` to `/`). ✓
- Rejects protocol-relative URLs (`//host`). ✓
- For absolute URLs, scheme + netloc must match `config.base_url`. ✓
- Default fallback is `/account/me`. ✓

**Auto-link behaviour:**
- `auto_link_verified_emails` (default unset/False): only links an existing user's
  account when `info.email_verified=True` from the provider. Unverified provider emails
  are rejected with `email_in_use`. ✓

**Identity conflicts:**
- Attempting to link an identity already attached to a different account → `identity_in_use`. ✓
- Attempting to unlink the sole sign-in method blocked by explicit check. ✓

**MFA gate on OAuth sign-in:**
- `enforce_mfa_on_oauth_signin` flag; when set, a second-factor SMS code is required
  even for OAuth logins. Link flows exempt (user was already authenticated). ✓

**Finding:** No new OAuth security issues found.
