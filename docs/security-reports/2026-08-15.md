## 🟠 WARNING

### W-1 (carry-over, day 4): `cryptography` floor ≥48.0.1 misses CVE-2026-69247

- **Files:** `pyproject.toml` lines 108 (oauth extra) and 154 (dev extra)
- **Locked version:** 49.0.0
- **Fixed version:** 50.0.0 (released 2026-07-31)
- **CVE:** CVE-2026-69247 — PKCS7 EnvelopedData decryption exposes a Bleichenbacher
  oracle through distinguishable errors and timing in `pkcs7_decrypt_der`,
  `pkcs7_decrypt_pem`, and `pkcs7_decrypt_smime`. Affects cryptography 44.0.0–49.x.
- **Impact:** regstack does not call PKCS7 decrypt directly (it uses `cryptography`
  only for JWKS-backed JWT signature verification via `pyjwt[crypto]`). However:
  (1) `pip install regstack[oauth]` resolves to 49.0.0, missing the fix;
  (2) any host using `cryptography` for PKCS7 operations in the same virtualenv
  inherits the exposure; (3) consumers auditing transitive dependencies will see
  an open advisory.
- **Fix:** Bump `cryptography` floor in `pyproject.toml`:
  ```toml
  # oauth extra
  oauth = ["pyjwt[crypto]>=2.13.0", "cryptography>=50.0.0", "httpx>=0.27"]
  # dev extra
  "cryptography>=50.0.0",
  ```
  Then update the comment block above (lines 98–107) and run `uv lock`.
- **Tracking:** GitHub Issue #172 (open since 2026-08-11, no PR yet).
  **Deadline: 2026-08-18 (3 days).**

## 🟡 INFO

### I-1: `tokens_invalidated_after` included in `UserPublic` API responses (intentional)

- **File:** `src/regstack/models/user.py:105–108`
- **Detail:** `UserPublic` includes `tokens_invalidated_after`. The inline
  docstring documents the design intent: SPAs comparing this field to their
  session JWT's `iat` can detect server-side revocation without an extra
  round-trip. The field reveals when the last password/email change occurred —
  low-sensitivity metadata. No action recommended unless future privacy
  requirements tighten.

### I-2: CLI `cmd:` log-source passes operator input to shell (intentional)

- **File:** `src/regstack/cli/validate/logtail.py:106`
- **Code:** `argv = ["sh", "-c", target]` where `target` is the
  operator-supplied value after `cmd:`.
- **Detail:** This is an operator-facing tool documented as accepting arbitrary
  shell commands. Runs only on operator workstations under operator credentials.
  No HTTP endpoint reaches this path. Design is intentional. **Note:** if ever
  exposed to untrusted input, the `cmd:` variant must be removed or sandboxed.

### I-3: PyJWT pinned at exact minimum with no headroom

- **File:** `pyproject.toml` line 55 — `pyjwt>=2.13.0`
- **Detail:** `pyjwt>=2.13.0` is simultaneously the floor and the latest
  upstream release. One new pyjwt advisory would make this floor insufficient
  with no buffer. Monitor weekly; bump floor promptly on any new release.

### §3 — Authentication & Authorization Audit

- All protected endpoints inject `Depends(rs.deps.current_user())` or
  `Depends(rs.deps.current_admin())`. All five bulk-revoke flows verified:
  password reset, password change, email-change confirm, admin disable
  (`set_tokens_invalidated_after`), account deletion (cascade
  `oauth_identities.delete_by_user_id` → `users.delete`).
- `AuthDependencies._authenticate` five-gate chain: scheme check → JWT decode →
  blacklist lookup → user/`is_active` check → bulk-revoke check.
- All API responses use `UserPublic.from_user()`. `hashed_password` excluded
  throughout.
- OAuth-only users (`hashed_password=None`): same generic 401 on password
  login; `require_password_set()` guards change-password, change-email,
  delete-account.
- Constant-time comparison via `pwdlib.PasswordHash` (Argon2id) — never `==`.
- Per-purpose key derivation via `derive_secret(jwt_secret, purpose)` (HMAC-SHA256)
  for all five purposes; compromise of one derived key does not expose others.

### §4 — Storage-layer Injection Safety

- **MongoDB:** No `$where`, `$expr`, `$function`, or `$accumulator` in any query.
  No user-supplied regex. `ObjectId.is_valid()` guard on all `get_by_id` paths.
  No unbounded `$in` from user input.
- **SQL:** All queries use SQLAlchemy Core expression API with parameterized binds.
  Two `text()` calls — `text("SELECT 1")` health ping and a migration pre-check —
  carry no user input. `UtcDateTime` TypeDecorator re-attaches UTC tzinfo on read.
  `purge_expired()` implementations use bound parameters.

### §5 — Input Validation & Injection

- Email templates: `MailComposer` uses `autoescape=select_autoescape(["html"])`.

- SSR templates: no `| safe`, no `{% autoescape false %}`, no `style="..."`.

### §6 — Rate Limiting & DoS Prevention

### §7 — Session & Token Security

- HS256 default; `len(raw) < 32` enforced at `JwtCodec.__init__`.
- `jti` required in decode options: `"require": ["sub", "exp", "iat", "jti",
  "purpose"]`. All encode paths produce `jti: secrets.token_urlsafe(16)`.
- `iat` emitted as float (`self.iat.timestamp()` — `jwt.py:69`). Microsecond
  precision preserved; bulk-revoke comparison `payload.iat <= cutoff` is safe.
- pyjwt `exp`/`iat` checks disabled in `JwtCodec`; re-validated against injected
  `Clock`. Same pattern in all custom token decode paths.
- Revocation chain in `_authenticate`: (1) Bearer scheme → 401; (2) JWT decode
  → generic 401; (3) `blacklist.is_revoked(jti)` → 401; (4) user lookup +
  `is_active` → 401; (5) `is_payload_bulk_revoked` → 401.
- No token values logged anywhere.

### §14 — OAuth Subsystem Audit

- **PKCE:** `code_verifier` stored server-side on state row; only SHA-256
  challenge (`code_challenge`) sent to provider. Verifier never appears in
  any URL.
- **State row lifecycle:** Missing row → `?error=bad_state`; expired row
  checked against `rs.clock.now()` (not `datetime.now(UTC)`). Atomic consume:
  Mongo uses `find_one_and_delete`; SQL wraps read+delete in a single
  `engine.begin()` transaction → no double-exchange.
- **ID-token verification:** Signature (via `PyJWKClient`), `iss`, `aud`,
  `exp`, `nonce`. All required claims enforced; `OAuthIdTokenError` raised
  on any failure with a generic outer message; specific failure logged but
  never echoed.
- **Auto-link policy:** Defaults `False`; fires only on `email_verified=True`
  when enabled. Identity in-use and already-linked cases return correct 409
  error codes.
- **Identity-row uniqueness:** `(provider, subject_id)` and `(user_id,
  provider)` unique at DB level (Mongo unique index, SQL `UniqueConstraint`).
- **OAuth-only user side effects:** Generic 401 on password login;
  `require_password_set()` guards all password-confirmation flows;
  `DELETE /oauth/{provider}/link` refuses with 400 on last sign-in method.
- **Hooks:** `oauth_signin_started`, `oauth_signin_completed`,
  `oauth_account_linked`, `oauth_account_unlinked` all present in
  `KNOWN_EVENTS`; router fires them at correct points.
