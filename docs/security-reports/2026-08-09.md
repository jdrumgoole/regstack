## 🟡 INFO (Best practice recommendations)

### I-1 · `UserPublic` exposes `tokens_invalidated_after` — acknowledged intentional design

**Section:** §9 — Data Exposure  
**File:** `src/regstack/models/user.py`, lines 105 and 126  
**Carry-over from:** 2026-08-08 (and prior reviews)

`UserPublic.tokens_invalidated_after` is included in API responses. The code carries an inline docstring explaining this is intentional: "SPAs comparing this to their session JWT's `iat` can tell when the token they hold has been invalidated by a password change / email change without making another request." This allows client-side preemptive re-auth without a separate check. The field does reveal when a password/email change occurred, which is low-sensitivity metadata. No action recommended unless future privacy requirements tighten; noting for continuity.

### I-2 · CLI `cmd:` log-source variant passes operator input to shell

**Section:** §5 — Input Validation & Injection  
**File:** `src/regstack/cli/validate/logtail.py`, lines ~67–69  
**New finding**

The `regstack validate --log-source cmd:<arbitrary shell command>` CLI path passes the user-supplied value via `["sh", "-c", target]`. This is an operator-facing tool explicitly documented as accepting "arbitrary shell commands" (docstring: "cmd:<arbitrary shell command>"). Since this runs only on operator workstations under the operator's own credentials — not as part of the HTTP API or any request path — the risk surface is limited to social engineering / script injection if an operator is tricked into running a malicious `--log-source` argument. No HTTP endpoint can reach this code path. **Noting for awareness only;** the current design is intentional. If this CLI is ever exposed to untrusted input (e.g., a web admin panel), the `cmd:` variant must be removed or sandboxed.

### §3 — Authentication & Authorization Audit

- All authenticated endpoints inject `rs.deps.current_user()` or `rs.deps.current_admin()`.
- All mutating endpoints require authentication; read-only public endpoints (`/forgot-password`, `/resend-verification`, `/reset-password`, `/verify`, OAuth callback) are correctly public and anti-enumeration-safe.
- `UserPublic.from_user()` is the only serialization path used on all API responses; `hashed_password` and raw `BaseUser` never appear in response bodies.
- Bulk-revoke discipline verified:
  - **Password reset** (`reset-password`): calls `users.update_password` (bumps `tokens_invalidated_after`) + `lockout.clear` + blacklists the reset `jti`. ✅
  - **Password change** (`change-password`): calls `users.update_password`. ✅
  - **Email-change confirm** (`confirm-email-change`): `users.update_email` bumps `tokens_invalidated_after`. ✅
  - **Admin disable** (`PATCH /admin/users/{id}` with `is_active=False`): calls `users.set_tokens_invalidated_after`. ✅
  - **Account deletion**: cascades `oauth_identities.delete_by_user_id` before `users.delete`. ✅
- OAuth-only users (`hashed_password=None`) handled correctly: login returns same generic 401 as a wrong-password attempt; `change-password`, `change-email`, `delete-account` return 400 with forgot-password pointer.
- Password comparison via `pwdlib.PasswordHasher.verify()` (constant-time Argon2id). No `==` comparison.
- JWT signing keys derived per-purpose via `derive_secret(jwt_secret, purpose)` — `session`, `password_reset`, `email_change`, `phone_setup`, `login_mfa` each get separate keys.

### §4 — Storage-layer Injection Safety

**MongoDB:**
- All query filters use pymongo's dict/operator interface — no string interpolation into query documents.
- No `$where`, `$expr`, `$function`, or `$accumulator` operators anywhere in `src/regstack/backends/mongo/`.
- No regex built from user input; no `re.compile` / `re.search` patterns using request data.
- `ObjectId.is_valid()` guards every URL-parameter ID before `ObjectId(user_id)` is called (`get_by_id`, `update_password`, `set_active`, `set_superuser`, `set_full_name`, `set_phone`, `update_email`, `delete`, etc.).
- `$in` queries not used with unbounded user-supplied arrays.

**SQL:**
- All queries use SQLAlchemy Core with parameterized binds (`select(...).where(col == value)`, `update(...).values(...)`).
- No `text()` calls with interpolation; `sa.text()` appears only in migration downgrade guard with a literal SQL string and no user input.
- `UtcDateTime` TypeDecorator in `src/regstack/backends/sql/types.py` attaches UTC on both write and read; regression from naive datetime would raise `TypeError` on comparison.
- `purge_expired()` across all SQL repos uses bound parameters for cutoff timestamps.

### §6 — Rate Limiting & DoS Prevention

- Login lockout: `LockoutService.check()` runs before password verification in `login.py`; locked accounts return 429 + `Retry-After` before any credential work. `record_failure` increments on all wrong-credential paths including OAuth-only and disabled/unverified accounts.
- `login_attempts` Mongo collection has TTL index sized to `login_lockout_window_seconds`. SQL backends rely on read-side filtering.
- Admin listing: `GET /admin/users` has `Query(ge=1, le=200)` cap on `limit`. ✅
- OAuth state TTL: Mongo has a TTL index on `oauth_states.expires_at`. SQL has `purge_expired()`.
- No file upload endpoints exist.

### §7 — Session & Token Security

- HS256 by default; `jwt_secret` minimum 32 chars enforced at `JwtCodec.__init__`.
- Every JWT includes `jti` (required by the decode `options["require"]` list); per-token revocation via `BlacklistRepo` works on all tokens.
- `iat` emitted as **float** via `payload.iat.timestamp()` in `TokenPayload.to_claims()`; `exp` as `int`. Bulk-revoke comparison `payload.iat <= cutoff` is microsecond-precise. ✅
- `JwtCodec` disables pyjwt's `verify_exp`/`verify_iat`/`verify_nbf` and validates against injected `Clock`. ✅
- `_authenticate` sequence verified:
  1. Bearer scheme check → 401
  2. `jwt.decode()` → 401 on failure (error message redacted, only "Invalid or expired token." returned)
  3. `blacklist.is_revoked(jti)` → 401
  4. `users.get_by_id(sub)` + `is_active` check → 401
  5. `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` → 401
- No token values appear in `log.info` or `log.error` calls in auth paths. The `hooks/redaction.py` module provides `redact_token()` used on all URL-bearing hook events.

### §14 — OAuth Subsystem Audit

- **14a PKCE:** `code_verifier` generated server-side and stored on the `oauth_states` row. Only the `code_challenge` (SHA-256 of verifier) goes to the authorization URL. Verified in `_begin_flow()` in `oauth.py`. ✅
- **14b State row lifecycle:** Callback checks for missing row (→ `?error=bad_state`) and expired row (→ `?error=state_expired`). Expiry comparison uses `rs.clock.now()`. `consume()` is atomic: Mongo uses `find_one_and_delete`; SQL wraps SELECT + DELETE in one transaction. ✅
- **14c ID-token verification:** `GoogleProvider.verify_id_token` validates: JWKS signature, `aud` = `client_id`, `iss` = issuer, `exp` > now, `nonce` = expected nonce, `sub` present and non-empty. On any failure raises `OAuthIdTokenError` with generic message; underlying exception logged at WARNING only. `require: ["sub", "iss", "aud", "exp", "iat", "nonce"]` enforced. ✅
- **14d Linking policy:** Default: Google sign-in for existing email-registered user → `?error=email_in_use`. Auto-link fires only when `oauth.auto_link_verified_emails=True` AND `email_verified=True`. Identity already linked to different user → `?error=identity_in_use`. Same identity, same user → `?error=already_linked`. ✅
- **14e OAuth-only user side effects:** `POST /login` with `hashed_password=None` → same generic 401. `change-password`, `change-email`, `delete-account` → 400 with forgot-password pointer. `DELETE /oauth/{provider}/link` → 400 ("last sign-in method") when no password and single provider. ✅
- **14f Identity-row uniqueness:** `(provider, subject_id)` and `(user_id, provider)` enforced as `UniqueConstraint` in SQL schema and as Mongo unique indexes. ✅
- **14g Hooks:** `oauth_signin_started`, `oauth_signin_completed`, `oauth_account_linked`, `oauth_account_unlinked` all in `KNOWN_EVENTS`. Fired at correct points in `routers/oauth.py`. ✅
