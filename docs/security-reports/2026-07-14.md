### W-3 — CVE-2026-45447: `cryptography` bundled OpenSSL heap UAF (CVSS 7.5 High) — carry-forward (day 18)

**Package:** `cryptography` (in `oauth` optional extra: `cryptography>=46.0.7`)
**Resolved (lock):** `47.0.0` · **Safe version:** `>=48.0.1`
**Advisory:** GHSA-537c-gmf6-5ccf · Published: June 9, 2026
**Tracked:** GitHub issue #123

All PyPI `cryptography` wheels `>=0.5.0,<48.0.1` bundle a statically-linked
OpenSSL vulnerable to CVE-2026-45447: a heap use-after-free in
`PKCS7_verify()` triggered by an empty `digestAlgorithms` SET in a crafted
PKCS#7/S/MIME message. The locked `47.0.0` is in the affected range. The
`oauth` extra floor `>=46.0.7` permits any version through `47.x`, all
vulnerable. Hosts that install `regstack[oauth]` and use `cryptography`
for other operations (TLS, S/MIME, PKCS#7 parsing) are directly exposed.

**Action required:**
1. Bump `oauth = ["pyjwt[crypto]>=2.13.0", "cryptography>=48.0.1"]` in
   `pyproject.toml`. Update the inline CVE comment to cite CVE-2026-45447.
2. Also bump `"cryptography>=48.0.1"` in the `dev` extra.
3. Run `uv lock`.

### W-4 — CVE-2026-53533: `aiosmtplib` SMTP command injection (CVSS 6.5) — carry-forward (day 18)

**Package:** `aiosmtplib`
**Floor:** `>=3.0` · **Resolved (lock):** `5.1.0` · **Safe floor:** `>=5.1.1`
**Tracked:** GitHub issue #124

The locked `5.1.0` is the vulnerable version. `SMTP.mail()`, `SMTP.rcpt()`,
`SMTP.vrfy()`, and `SMTP.expn()` send caller-supplied email addresses to
the server without rejecting C0 control characters (0x00–0x1F and DEL
0x7F), including CR, LF, and NUL. An address containing a CRLF sequence
can inject arbitrary SMTP commands into the session. Version 5.1.1 raises
`ValueError` on any address containing control characters.

**Exposure in regstack:** The SMTP backend (`SmtpEmailService`,
`src/regstack/email/backends/smtp.py`) uses `aiosmtplib` to send email
verification, password-reset, MFA, and email-change confirmation messages.
These emails are addressed to user-supplied email addresses. A crafted
address containing CRLF can inject SMTP commands at the wire level — below
Jinja2 template rendering, which cannot protect against wire-level injection.

**Action required:**
1. Bump `"aiosmtplib>=5.1.1"` in `pyproject.toml`. Update the inline
   comment to add CVE-2026-53533 and cite `5.1.1` as the safe floor.
2. Run `uv lock`.

## 🟡 INFO (Best practice recommendations)

### I-1 — `UserPublic` exposes `tokens_invalidated_after` and `phone_number` (carry-forward)

`UserPublic` exposes `tokens_invalidated_after` (intentional — allows SPA
clients to detect bulk-revocation without an extra round-trip) and
`phone_number` (design decision). Hosts with stricter PII requirements
should subclass `UserPublic` or add a projection step. No code change
required in regstack itself.

### I-2 — `admin_promote_pending` path parameter not validated as `EmailStr` (carry-forward)

`POST /admin/pending/{email}/promote` (`src/regstack/routers/admin.py:204`)
accepts `email: str = Path(...)`. A syntactically invalid email address
passes parameter binding and returns 404 (LookupError path). The endpoint
is admin-gated so the risk is low. Fix is a one-liner:
`email: Annotated[EmailStr, Path(...)]`.

### I-3 — Duplicate tracking issue for python-multipart cluster (carry-forward, day 18)

Issues #118 (2026-06-23) and #120 (2026-06-24) both track the
python-multipart floor bump. Close #118 as a duplicate of #120; update
#120 to enumerate all four CVEs (CVE-2026-53537/53538/53539/53540) and
record the `>=0.0.32` safe floor. (Tracked within W-1 above.)

### I-4 — CVE-2026-48524 missing from pyjwt comment in `pyproject.toml` (carry-forward)

**Package:** `pyjwt` · **CVE:** CVE-2026-48524 · **CVSS:** 3.7 (Low)
**Advisory:** GHSA-fhv5-28vv-h8m8

`PyJWKClient.get_signing_key()` forces a fresh HTTP request to the JWKS
endpoint on every call when a key is absent from its in-memory cache.
Under sustained load this can exhaust connection pools (DoS). Fixed at
`>=2.13.0` (the current lock and floor). The gap is only the missing CVE
number in the `pyproject.toml` comment. Add CVE-2026-48524 alongside the
existing CVE-2026-48522/48523/48525/48526 entries when making the next
`pyproject.toml` edit (e.g. during the W-1/W-4 floor bumps).

### §3 — Authentication & authorization

All endpoints that mutate user state or return user data are gated by
`rs.deps.current_user()` or `rs.deps.current_admin()`. `UserPublic.from_user()`
is the only serialisation path in responses — `hashed_password` excluded.
Bulk-revoke discipline confirmed:

- **Password reset:** calls `users.update_password` (bumps
  `tokens_invalidated_after`) AND `lockout.clear`, blacklists reset JWT
  `jti`. ✓
- **Password change:** calls `users.update_password` AND `lockout.clear`. ✓
- **Email-change confirm:** calls `users.update_email` (bumps
  `tokens_invalidated_after`). ✓
- **Admin disable:** calls `set_tokens_invalidated_after` immediately after
  `set_active`. ✓
- **Account deletion:** cascades `oauth_identities` first, then deletes
  user. ✓

OAuth-only user (`hashed_password=None`) handling: `POST /login` returns
the same generic 401 as a wrong-password attempt (no enumeration).
`change-password`, `change-email`, `delete-account` return 400 via
`require_password_set()`. ✓

Password verification uses `pwdlib.PasswordHasher.verify()` (Argon2id). ✓

JWT signing keys derived per-purpose via HMAC-SHA256
(`config/secrets.py:derive_secret`). ✓

### §4 — Storage-layer injection safety

**MongoDB:** All queries use pymongo's parameterised dict API. No `$where`,
`$expr`, `$function`, or `$accumulator` operators. No user-input regex.
`ObjectId.is_valid()` checked before `ObjectId(user_id)` on every Mongo
repo method. No unbounded `$in` arrays from user input.

**SQL:** All queries use SQLAlchemy Core with bound parameters. Two
`text()` calls exist (`SELECT 1` ping, migration `SELECT COUNT(*)`) — both
without user-controlled inputs. `UtcDateTime` TypeDecorator correctly
re-attaches UTC on all reads. `purge_expired()` uses bound timestamp
parameters.

### §5 — Input validation & injection

All API input bodies use Pydantic models with `extra="forbid"`. `EmailStr`
validation on all email-bearing fields. E.164 phone validation via
`is_valid_e164()` called in `routers/phone.py` before storage. Email
templates use Jinja2 `select_autoescape(["html"])`. No `| safe` filters or
`{% autoescape false %}` blocks in any UI or email template. OAuth
`redirect_to` validated same-origin in `_validate_redirect()` including
backslash and protocol-relative URL rejection. CLI wizard inputs are not
passed to shell commands.

### §6 — Rate limiting & DoS prevention

Login lockout called before password verification. Mongo `login_attempts`
TTL index sized to `login_lockout_window_seconds`. Admin pagination caps
`limit` at `le=200`. OAuth state TTL 300s default, completion window 30s.
No file uploads added.

### §7 — Session & token security

JWT HS256; `jwt_secret` non-empty enforced at construction. Every JWT
includes `jti`. `iat` emitted as float (confirmed in
