## 🟠 WARNING

### W-1 (carry-over, day 11 — DEADLINE MISSED 2026-08-18)

**Section:** §1 — Dependency Vulnerability Check
**CVE:** CVE-2026-69247 — `pkcs7_decrypt` Bleichenbacher oracle
**Affected:** `cryptography` ≥ 44.0.0, < 50.0.0
**Fix available on PyPI:** `cryptography==50.0.0` released **2026-07-31** (21 days ago)
**Fix required:** Bump floor to `cryptography>=50.0.0` in `oauth` and `dev` extras in `pyproject.toml`; run `uv lock`
**Tracking:** GitHub issue #181 (`[security] Raise cryptography floor to >=50.0.0`), open since 2026-08-19 — no fix PR, no assignee

`pyproject.toml` HEAD (`2014645`) still declares:
```toml
oauth = ["pyjwt[crypto]>=2.13.0", "cryptography>=48.0.1", "httpx>=0.27"]
...
"cryptography>=48.0.1",   # in dev extra
```

As of `uv.lock`, the resolved version is 49.0.0 — within the affected range (≥44.0.0, <50.0.0).

**Technical impact:** `pkcs7_decrypt_der`, `pkcs7_decrypt_pem`, and `pkcs7_decrypt_smime` exposed distinguishable error paths and timing differences during RSA `RecipientInfo.encryptedKey` decryption, constituting a Bleichenbacher oracle. An attacker submitting adaptive chosen ciphertext to a service reflecting the outcome can recover the RSA content-encryption key. regstack itself does not call PKCS#7 decrypt, but `pip install regstack[oauth]` resolves to 49.0.0 by default, shipping a version with an open advisory to all consumers. The fix (cryptography 50.0.0) substitutes a random key on RSA decryption failure per RFC 3218.

**Urgency escalation:** The fix version has been available on PyPI for 21 days. A PR with a two-line change to `pyproject.toml` plus `uv lock` is all that is required. Continued inaction ships a known-vulnerable transitive dependency to every consumer of `regstack[oauth]`.

### I-4 (NEW) — CVE-2026-13061 in MongoDB Server (not driver) — host awareness

**CVE-2026-13061** (CVSS: Medium, published August 2026) is an improper access control vulnerability in the MongoDB **server** itself (`$listSessions` command leaks session data across users; affects mongod 7.0.0–7.0.38, 8.0.0–8.0.27, 8.3.0–8.3.6). The PyMongo driver (`pymongo>=4.9`) is not affected. regstack ships no server; this is the wire-protocol server deployed by the host.

This is flagged as INFO to raise awareness for regstack users who self-host MongoDB: upgrade their mongod instance to 7.0.39+, 8.0.28+, or 8.3.7+ as applicable. No action required on regstack's dependency manifest.
