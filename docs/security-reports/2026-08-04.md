### §3 — Authentication & Authorization Audit

Every endpoint that returns user data or mutates user state requires either `Depends(rs.deps.current_user())` or `Depends(rs.deps.current_admin())`. Admin-only endpoints all use `current_admin()`.

All user data in responses goes through `UserPublic.from_user(...)`, which excludes `hashed_password`.

**Bulk-revoke discipline — confirmed present:**
- `POST /reset-password` → `users.update_password(...)` (bumps `tokens_invalidated_after` in both backends) + `lockout.clear(email)`. ✓
- `POST /change-password` → `users.update_password(...)` + `lockout.clear(...)`. ✓
- `POST /confirm-email-change` → `users.update_email(...)` (bumps `tokens_invalidated_after`) + `lockout.clear(previous_email)`. ✓
- `PATCH /admin/users/{id}` with `is_active=false` → `users.set_tokens_invalidated_after(user.id, rs.clock.now())` called immediately after `set_active`. ✓ (`routers/admin.py:112`)
- `DELETE /account` and `DELETE /admin/users/{id}` → `oauth_identities.delete_by_user_id(user.id)` before `users.delete(user.id)` to prevent orphaned identity rows. ✓

**OAuth-only users (`hashed_password=None`):** `POST /login` checks `user.hashed_password is None` and falls through to `record_failure` + same generic 401 as a wrong-password attempt — no enumeration of OAuth-only status. `change-password`, `change-email`, `delete-account` invoke `require_password_set(user)` which returns 400. ✓

**Password comparison:** `rs.password_hasher.verify(plaintext, hash)` via `pwdlib` (Argon2id constant-time). Never `==`. ✓

**JWT key isolation:** `derive_secret(jwt_secret, purpose)` — HMAC-SHA256 of master secret keyed on the purpose string (`hmac.new(master, purpose.encode("utf-8"), hashlib.sha256).digest()`). Session tokens cannot satisfy password-reset, email-change, phone-setup, or login-MFA verification. ✓

### §4 — Storage-layer Injection Safety

**MongoDB (`src/regstack/backends/mongo/repositories/`):**
- No `$where`, `$expr`, `$function`, or `$accumulator` operators. All query filters use Python dict literals with user-supplied values as document field values, never as operators. ✓
- No user-input regex patterns (`re.compile`/`re.match` not present in backends). ✓
- `UserRepo` guards every `user_id` use with `ObjectId.is_valid(user_id)` before calling `ObjectId(user_id)` — malformed IDs return `None` or no-op. `OAuthIdentityRepo` does not take user_id as a URL parameter; it uses the authenticated user's id from the JWT payload, which is stored as a string. ✓
- No unbounded `$in` arrays from user input. ✓

**SQL (`src/regstack/backends/sql/repositories/`):**
- All queries use SQLAlchemy Core expression API with parameterised column comparisons. No f-string or `%` interpolation into raw SQL. ✓
- Two `text(...)` usages: `text("SELECT 1")` (health-check ping, no user input) and `sa.text("SELECT COUNT(*) FROM users WHERE hashed_password IS NULL")` (migration downgrade guard, static string). Both safe. ✓
- `UtcDateTime` TypeDecorator (`backends/sql/types.py`) consistently attaches UTC in both `process_bind_param` (write) and `process_result_value` (read). No path that could return a naive datetime to the bulk-revoke comparison. ✓
- `purge_expired()` implementations across all SQL repos use bound timestamp parameters. ✓

### §6 — Rate Limiting & DoS Prevention

- `LockoutService.check(payload.email)` is the first call in `POST /login`, before user lookup and password verification. A locked attacker cannot probe whether their guess is right. ✓
- `lockout.record_failure` fires on: user not found, wrong password (`hashed_password is None` or failed verify), correct-password-but-inactive, correct-password-but-unverified. All branches increment the counter. ✓
- `GET /admin/users` pagination: `limit: Annotated[int, Query(ge=1, le=200)] = 50` — capped at 200. ✓
- MongoDB `login_attempts` has a TTL index sized to `config.login_lockout_window_seconds`. SQL backends filter by `when >= now - window` plus `purge_expired()`. ✓
- OAuth state rows: Mongo has a TTL index (`oauth_state_ttl`, `expireAfterSeconds=0` on `expires_at`). SQL backends expose `purge_expired()`. Default TTL is 5 minutes. ✓
- No file-upload endpoints introduced. ✓

### §7 — Session & Token Security

- JWT algorithm: HS256, secret validated `>= 32 chars` at `JwtCodec.__init__` — raises `ValueError` on short or empty secret, failing closed. ✓
- Every JWT includes `jti` (`secrets.token_urlsafe(16)` — 128 bits). Per-token blacklist revocation depends on it. ✓
- `iat` emitted as `float` (`now.timestamp()`) so a login completing microseconds after a bulk-revoke cutoff has `iat > cutoff` and is not falsely rejected. `exp` is `int` (precision immaterial for expiry). ✓
- `JwtCodec.decode` disables pyjwt's `verify_exp`/`verify_iat`/`verify_nbf` and re-validates both against the injected `Clock` — `FrozenClock` tests stay deterministic; production uses `SystemClock`. ✓
- `_authenticate` order: decode → 401 on `TokenError`; `blacklist.is_revoked(jti)` → 401; `users.get_by_id(sub)` + `is_active` check → 401; `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` → 401. All four gates present in documented order. ✓
- Token values (`access_token`, `id_token`) do not appear in `log.info`/`log.warning`/`log.error`. OAuth warning logs use `%s` formatting with `exc` (exception messages only, not token values). OAuth callback error from provider is sanitized via `safe_error` before logging. ✓

### §14 — OAuth Subsystem Audit

**14a. PKCE invariants:** `_begin_flow` generates `code_verifier = secrets.token_urlsafe(64)` server-side and stores it on the `OAuthState` row. Only `code_challenge = base64url(sha256(code_verifier))` appears in the provider authorization URL. The verifier never appears in the redirect URL. ✓

**14b. State row lifecycle:** Missing row → `?error=bad_state`. Expired row → `?error=state_expired` (comparison uses `rs.clock.now()`, not `datetime.now(UTC)`). `oauth_states.consume(payload.id)` uses `find_one_and_delete` (Mongo) — atomic read-and-delete so a second exchange with the same ID returns `None` → 404. After a successful callback the state row's expiry is shortened to `oauth.completion_ttl_seconds` (default 30 s). ✓

**14c. ID-token verification:** `GoogleProvider.verify_id_token` validates signature against Google JWKS (`PyJWKClient` with `timeout=5`), checks `iss == GOOGLE_ISSUER`, `aud == client_id`, `exp`/`iat` via pyjwt defaults, and `nonce` against `state_row.nonce`. Uses `options={"require": ["sub", "iss", "aud", "exp", "iat", "nonce"]}`. Any failure raises `OAuthIdTokenError`; the specific reason is logged at WARNING but never echoed in the redirect. ✓

**14d. Linking-policy enforcement:** Auto-link fires only when `oauth.auto_link_verified_emails=True` AND `info.email_verified=True`. Identity already on a different account → `?error=identity_in_use`. Relinking the same identity to the same account → `?error=already_linked`. ✓

**14e. OAuth-only user side effects:** `POST /login` returns the same generic 401 for `hashed_password=None` users as for wrong-password attempts. `change-password`, `change-email`, `delete-account` call `require_password_set(user)` → HTTP 400. `DELETE /oauth/{provider}/link` refuses if `not has_password and other_identities == 0`. ✓

**14f. Identity-row uniqueness:** Mongo: unique indexes on `(provider, subject_id)` (`provider_subject_unique`) and `(user_id, provider)` (`user_provider_unique`) — confirmed in `backends/mongo/indexes.py:73–87`. SQL: matching `UniqueConstraint` declarations in `backends/sql/schema.py:143–144`. Parity confirmed. ✓

**14g. Hook events:** `oauth_signin_started`, `oauth_signin_completed`, `oauth_account_linked`, `oauth_account_unlinked` all present in `hooks/events.KNOWN_EVENTS`. ✓

### §15 — Multi-backend Parity & Schema Migration Safety

**15a. CI matrix:** `test.yml` runs `pytest -n auto` across Python 3.11 and 3.12, with MongoDB and PostgreSQL as service containers, SQLite inline, and SecantusDB embedding its own server per xdist worker. All four backends exercise the same parametrized suite on every push. ✓

**15b. Schema migration safety:** Three migrations — `0001_initial_schema.py`, `0002_oauth.py`, `0003_oauth_state_result_was_new.py`. All three have `upgrade()` and `downgrade()`. `0002` uses `batch_alter_table` for the `hashed_password` nullability change (SQLite-safe). `0003` uses `batch_alter_table` for the `result_was_new` `ADD COLUMN` (SQLite-safe). ✓

**15c. Mongo index parity:** Every SQL `UniqueConstraint` has a matching Mongo unique index:
- `users.email` UNIQUE → `email_unique` (Mongo). ✓
- `oauth_identities (provider, subject_id)` UNIQUE → `provider_subject_unique` (Mongo). ✓
- `oauth_identities (user_id, provider)` UNIQUE → `user_provider_unique` (Mongo). ✓
- TTL parity: all `expires_at`-bearing collections have Mongo TTL indexes. SQL backends have `purge_expired()` with bound timestamp parameters. ✓

**15d. Datetime tz-awareness:** `make_client(tz_aware=True)` for Mongo. `UtcDateTime` TypeDecorator re-attaches UTC in `process_result_value` on every read. No naive-datetime path reaching the bulk-revoke comparison. ✓
