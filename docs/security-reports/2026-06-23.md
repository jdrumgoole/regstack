## 🟠 WARNING (Address within 1 week)

### W-1 — CVE-2026-53539: python-multipart Quadratic-Complexity DoS (CVSS High)

**Package:** `python-multipart`
**Current floor:** `>=0.0.27` · **Resolved in `uv.lock`:** `0.0.28` (uploaded 2026-05-10)
**Fixed in:** `0.0.30`

The `QuerystringParser` inside `python_multipart/multipart.py` processes
`application/x-www-form-urlencoded` POST bodies with an algorithm that
scans the remainder of the buffer searching for `&` on each semicolon it
encounters. For inputs that use `;` as the field separator (an older
non-WHATWG convention), this produces `O(B²)` byte comparisons where `B`
is the buffer size. A crafted request body consisting of many semicolons
stalls the process on pure-Python CPU work, enabling unauthenticated
Denial of Service.

regstack mounts `python-multipart` unconditionally as a FastAPI dependency
(FastAPI uses it for form/body parsing). Every auth endpoint that accepts
a JSON body is served by the same Starlette/FastAPI stack and is therefore
reachable by this crafted payload before any authentication occurs.

**Action:** Bump the floor in `pyproject.toml` to
`python-multipart>=0.0.30` and run `uv lock`. Update the inline CVE
comment to add CVE-2026-53539. Open a separate `[security]` issue to
track the change.

## 🟡 INFO (Best practice recommendations)

### I-1 — `UserPublic.tokens_invalidated_after` and `phone_number` exposure (carry-forward)

`UserPublic` (`src/regstack/models/user.py:105,100`) includes both
`tokens_invalidated_after` and `phone_number` in all API responses that
return a user object (e.g., `GET /me`, `PATCH /me`, `POST /confirm-email-change`,
and every admin endpoint).

`tokens_invalidated_after` is intentional and documented in
`docs/security.md` — it lets SPA clients detect when their cached session
JWT has been bulk-revoked without a round-trip to the server. The
`phone_number` field is a design decision carried forward from the 2026-05-21
and 2026-06-20 reviews (I-1, I-2, and I-3 respectively). Hosts that
consider phone numbers sensitive should wrap `UserPublic` with a narrower
projection model. No code change in regstack; still the documented design
trade-off.

### I-2 — `admin_promote_pending` path parameter not validated as `EmailStr`

`POST /admin/pending/{email}/promote`
(`src/regstack/routers/admin.py:202`) takes `email: str = Path(...)`.
The value is passed directly to `rs.promote_pending(email)` which calls
`pending.find_by_email(email)` — a parameterised DB lookup with no further
validation. No injection is possible, but a malformed address (e.g.,
`not-an-email`) passes validation silently and returns a 404 rather than a
400. The endpoint is admin-only (`current_admin()` dependency) so the attack
surface is constrained; this is a minor best-practice gap rather than a
security risk.

**Action:** Replace `email: str = Path(...)` with
`email: Annotated[EmailStr, Path(...)]` so FastAPI rejects syntactically
invalid addresses at the binding layer with a 422, consistent with all
other email-bearing endpoints.

### §3 — Authentication & authorization

- Every authenticated endpoint injects `rs.deps.current_user()` or
  `rs.deps.current_admin()`. No route returns user data without going
  through `UserPublic.from_user()`.
- Bulk-revoke discipline: password reset calls `update_password` (which
  bumps `tokens_invalidated_after`) **and** `lockout.clear`; `change-password`
  bumps hash + cutoff; `confirm-email-change` bumps cutoff via
  `update_email`; admin `PATCH /admin/users/{id} {is_active: false}` calls
  `set_tokens_invalidated_after`; account deletion cascades
  `oauth_identities` before `users.delete`.
- OAuth-only users (`hashed_password=None`): login returns the same
  generic 401 as a wrong-password attempt (no enumeration). `change-password`,
  `change-email`, `delete-account` return 400 via `require_password_set`.
- Password comparison uses `pwdlib.PasswordHasher.verify` (Argon2id
  constant-time), never `==`.
- JWT signing keys are purpose-derived via HMAC-SHA256
  (`config/secrets.derive_secret`); compromise of a session key cannot
  replay as a password-reset key.

### §4 — Storage-layer injection

**MongoDB:** All query filters in `backends/mongo/repositories/` use
Python dict literals with caller-supplied values as document values —
not as operators. No `$where`, `$expr`, `$function`, or `$accumulator`
usage. No regex patterns built from user input. `ObjectId.is_valid()`
guards on every method accepting a `user_id` string before passing to
`ObjectId(user_id)`. No unbounded `$in` arrays from user input.

**SQL:** All queries in `backends/sql/repositories/` use SQLAlchemy Core
with parameterised column comparisons (`self._t.c.email == email`, etc.).
Two `text()` usages found: `text("SELECT 1")` (health-check ping, no
user input) and `sa.text("SELECT COUNT(*) FROM users WHERE hashed_password IS NULL")`
(migration downgrade guard, static SQL, no user input). Both safe.
`UtcDateTime` TypeDecorator correctly re-attaches UTC on both write and
read paths; no naive datetime regression. `purge_expired()` implementations
use bound timestamp parameters.

### §5 — Input validation & injection

All API request bodies use Pydantic models with `extra="forbid"`.
`EmailStr` validation on all email fields. `is_valid_e164()` called
before phone number storage (`routers/phone.py:61`). Jinja2 email
templates use autoescape (no `| safe` or `{% autoescape false %}` in
`src/regstack/email/templates/`). UI templates have no `| safe` filters
or autoescape overrides. `regstack init` CLI wizard writes config via
`tomlkit`, no shell command construction from user input. `redirect_to`
in OAuth start/link routes is validated by `_validate_redirect()` against
`config.base_url`, including backslash normalization defence and
protocol-relative URL rejection.

### §6 — Rate limiting & DoS prevention

Login lockout fires `lockout.check()` before password verification so an
already-locked attacker cannot probe whether their guess was right.
`record_failure` fires for every failed branch (wrong password, inactive
account, unverified account). Mongo `login_attempts` has a TTL index
sized to `login_lockout_window_seconds`. Admin `/admin/users` endpoint
caps `limit` with `Query(ge=1, le=200)`. OAuth state rows have a TTL
index (`oauth_state_ttl`) on `expires_at` for Mongo; SQL backend
exposes `purge_expired()`. No file-upload endpoints introduced.

### §7 — Session & token security

JWT uses HS256 by default, secret enforced non-empty at `JwtCodec`
construction. Every token includes `jti` (16-byte `secrets.token_urlsafe`).
`iat` emitted as a float (RFC 7519 NumericDate) so microsecond-precision
bulk-revoke comparisons work. `JwtCodec` disables pyjwt's `exp`/`iat`
checks and validates them against the injected `Clock`. `_authenticate`
chain: decode → blacklist `jti` check → active user check →
`is_payload_bulk_revoked` — all four gates present. No token values
appear in log output at INFO or above.

### §14 — OAuth subsystem

**14a — PKCE invariants:** `_begin_flow` generates `code_verifier` via
`secrets.token_urlsafe(64)` and stores it on the `OAuthState` row. Only
the `code_challenge` (SHA-256 of the verifier, base64url) is passed to
the provider's authorization URL. The verifier never appears in the
redirect.

**14b — State row lifecycle:** The `state` parameter the browser carries
is the random `state_id` (`secrets.token_urlsafe(32)`). Callback looks up
the row via `find(state)`, rejects missing or wrong-provider rows with
`?error=bad_state`, and checks `state_row.expires_at < rs.clock.now()`
(using the injected clock, not `datetime.now()`). `consume()` uses
`find_one_and_delete` (Mongo) — atomic read-and-delete so a second
`/oauth/exchange` call with the same ID returns `None → 404`.

**14c — ID-token verification:** `GoogleProvider.verify_id_token`
verifies signature against Google's JWKS (via `PyJWKClient` with a
configured timeout), checks `iss == GOOGLE_ISSUER`, `aud == client_id`,
`exp`, `iat`, and `nonce`. All failures raise `OAuthIdTokenError` —
the specific reason is logged at WARNING but never echoed in the redirect.

**14d — Linking policy:** Default: Google sign-in for an existing
email-registered user raises `_LinkConflictError("email_in_use")`.
Auto-link fires only when `oauth.auto_link_verified_emails=True` and
`id_token.email_verified=True`. An identity already linked to a different
user raises `identity_in_use`; re-linking the same identity to the same
user raises `already_linked`.

**14e — OAuth-only user side effects:** Login rejects `hashed_password=None`
users with the same generic 401 as wrong-password. `change-password`,
`change-email`, `delete-account` return 400 via `require_password_set`.
`DELETE /oauth/{provider}/link` returns 400 (`last sign-in method`) when
the user has no password and only one identity.

**14f — Identity-row uniqueness:** Mongo unique indexes on
`(provider, subject_id)` (`provider_subject_unique`) and
`(user_id, provider)` (`user_provider_unique`) present in
`backends/mongo/indexes.py:72-86`. SQL `UniqueConstraint` on the same
pairs in `0002_oauth.py:47-48`. Parity confirmed.

**14g — Hooks:** `oauth_signin_started`, `oauth_signin_completed`,
`oauth_account_linked`, `oauth_account_unlinked` all present in
`hooks/events.KNOWN_EVENTS`. Router fires them at the correct points.
