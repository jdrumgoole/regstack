## 🟠 WARNING (Address within 1 week)

### W-1 — PyJWKClient missing timeout (`src/regstack/oauth/providers/google.py:83`) — CARRIED OVER

**Status:** Unaddressed since 2026-05-22 review (W-1). No code change in the interim.

**Finding:**

```python
self._jwks_client = PyJWKClient(jwks_url, cache_keys=True)
```

`PyJWKClient` performs a synchronous `urllib.request.urlopen` on a JWKS cache miss. PR #80
offloaded this to `asyncio.to_thread` so it no longer blocks the event loop, but the underlying
`urllib` call still has no timeout (`timeout=None` → indefinite). Under a sustained Google JWKS
outage or network partition, concurrent cache-miss events each hold a worker thread indefinitely.
Python's default asyncio thread pool is bounded (min(32, os.cpu_count() + 4) threads); exhausting
it blocks all `asyncio.to_thread` calls across the application.

**Fix** (one line):

```python
self._jwks_client = PyJWKClient(jwks_url, cache_keys=True, timeout=5)
```

`PyJWT >= 2.4` accepts `timeout` on `PyJWKClient.__init__`. The project already requires
`pyjwt>=2.12.1`, so the parameter is available.

### I-1 — `was_new_account` always `False` in OAuth exchange response — CARRIED OVER

**Status:** Unaddressed since 2026-05-22 review (I-1).

`ExchangeResponse.was_new_account` is hardcoded to `False` in `POST /oauth/exchange`
(`src/regstack/routers/oauth.py:176`). The `was_new` boolean is correctly computed in
`_resolve_user` during the callback but is not persisted to the `oauth_states` row, so the
exchange endpoint cannot surface it. Not a security issue — a SPA seeing `False` for a genuinely
new account creates no exploitable condition — but it is an API accuracy gap. Fix: add a
`result_was_new: bool = False` column to `oauth_states` and populate it during the callback.

### I-3 — OAuth token-exchange logs full Google response body — CARRIED OVER

**Status:** Unaddressed since 2026-05-22 review (I-3).

`src/regstack/oauth/providers/google.py:143-145`:

```python
raise OAuthTokenExchangeError(
    f"google token exchange failed: {response.status_code} {response.text}"
)
```

Caught in `routers/oauth.py` and logged at `WARNING`. The user sees only
`?error=token_exchange_failed`; nothing leaks to the client. Google token-endpoint error responses

improvement: split status-code (WARNING) from body (DEBUG) to reduce log noise:


### §3 — Authentication & Authorization

- Every authenticated endpoint injects `rs.deps.current_user()` or `rs.deps.current_admin()`.

  `/login`, `/forgot-password`, `/verify`, `/resend-verification`, `/reset-password`,

- Bulk-revoke discipline verified on both backends:
  - `update_password` → bumps `tokens_invalidated_after` ✓
  - `update_email` → bumps `tokens_invalidated_after` ✓
  - `set_active(id, False)` → calls `set_tokens_invalidated_after` ✓ (admin.py:111)

### §6 — Rate Limiting & DoS Prevention

- `LockoutService.check()` fires at the very top of `POST /login`, before any user lookup or
  password verification. A locked account always gets 429 + `Retry-After`.
- `record_failure` is called for every failure branch (user not found, wrong password, disabled,
  unverified). Even a correct-password-but-disabled account increments the lockout counter (login.py
  comment explains the adversarial rationale).
- Mongo `login_attempts` TTL index expires rows after `login_lockout_window_seconds`.
- SQL `login_attempt_repo.purge_expired()` uses bound parameter cutoff; `count_recent` uses
  parameterised window comparison.
- Admin `/admin/users` listing: `Query(ge=1, le=200)` on `limit` — unbounded queries prevented.
- OAuth `state` rows: Mongo TTL index on `expires_at` + `purge_expired()` for SQL backends.
  Default `state_ttl_seconds` is 5 minutes; shortened to `completion_ttl_seconds` (default 30s)
  after the callback resolves to bound the token-theft window.
- Per-route IP rate limiting (`slowapi`) is available for all auth-sensitive routes via config
  (`login_rate_limit`, `register_rate_limit`, `forgot_password_rate_limit`, etc.) and enforced at
  construction time when config strings are non-empty.

### §7 — Session & Token Security

- HS256 by default; secret ≥32 chars enforced at `JwtCodec.__init__` (raises `ValueError` on
  empty secret).
- Every JWT includes `jti` generated with `secrets.token_urlsafe(16)`.
- `iat` emitted as a **float** (RFC 7519 NumericDate) — sub-second precision enables correct
  `iat <= cutoff` bulk-revoke comparisons when a login completes in the same wall-clock second as a
  password change. `exp` encoded as `int` for broad client compatibility.
- pyjwt's `exp`/`iat`/`nbf` automatic checks disabled; both validated against the injected
  `Clock`. `FrozenClock`-driven tests and production correctness both rely on this seam.
- `_authenticate` order: decode → blacklist (`jti`) check → user lookup + `is_active` check →
  bulk-revoke (`iat <= tokens_invalidated_after`) check. Correct.
- Password-reset tokens blacklisted on first use via `blacklist.revoke(token_payload.jti, ...)`,
  preventing replay (`password.py:117`).
- No token values appear in any log call. Token decode errors return a single static
  "Invalid or expired token." 401 — specific `pyjwt` rejection reason never echoed.

### §14 — OAuth Subsystem Audit

**§14a — PKCE invariants:** `code_verifier` generated server-side
(`secrets.token_urlsafe(64)`), stored on the `oauth_states` row. Only
`code_challenge = base64url(sha256(verifier))` reaches the provider. Verifier never appears
in any redirect URL or response body. ✓

**§14b — State row lifecycle:**
- `oauth_states.find()` in the callback is read-only (does not consume the row).
- `oauth_states.consume()` in `/oauth/exchange` uses `find_one_and_delete` (Mongo — atomic) or
  SELECT + DELETE inside `engine.begin()` (SQL — transactional). A second concurrent exchange
  call sees `None` → 404. ✓
- Expiry is checked against `rs.clock.now()` (not bare `datetime.now(UTC)`) — clock injection
  preserved for tests. ✓
- After callback completes, `result_token` window is shortened to `completion_ttl_seconds`
  (default 30s), bounding the stolen-state-id window. ✓

**§14c — ID-token verification:** Validates signature (RS256, `PyJWKClient`), `iss` = `GOOGLE_ISSUER`,
`aud` = `client_id`, `exp > now` (pyjwt validates with required claims), `nonce` = `state_row.nonce`.
Any failure raises `OAuthIdTokenError`; internal detail is logged server-side; user sees
`?error=id_token_failed`. ✓

**§14d — Linking policy:**
- Existing email + no `auto_link_verified_emails` → `email_in_use`. ✓
- `auto_link_verified_emails=True` + `email_verified=True` → auto-link. ✓
- Already-linked identity to a different user → `identity_in_use`. ✓
- Same identity to same user → `already_linked`. ✓

**§14e — OAuth-only user side effects:**
- `POST /login` → same generic 401 as wrong password. ✓
- `change-password`, `change-email`, `delete-account` → `require_password_set()` 400. ✓
- `DELETE /oauth/{provider}/link` with `hashed_password=None` and last provider → 400 "Cannot
  unlink your only sign-in method." ✓

**§14f — Identity-row uniqueness:**
- `(provider, subject_id)` UNIQUE: Mongo `provider_subject_unique` index; SQL `UniqueConstraint`. ✓
- `(user_id, provider)` UNIQUE: Mongo `user_provider_unique` index; SQL `UniqueConstraint`. ✓

**§14g — Hooks:** `oauth_signin_started`, `oauth_signin_completed`, `oauth_account_linked`,
`oauth_account_unlinked` present in `KNOWN_EVENTS` and fired at the correct points in
`routers/oauth.py`. ✓
