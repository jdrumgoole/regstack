### W-1 — CVE-2026-69247: cryptography floor too low (day 38, SLA overdue 23 days)

**Tracking:** Issue #181  
**File:** `pyproject.toml`  
**Floor:** `cryptography>=48.0.1`  
**Fix required:** `cryptography>=50.0.0`

CVE-2026-69247 is a memory-safety vulnerability in the `cryptography` package's Rust extension affecting versions before 50.0.0. The current floor of `>=48.0.1` permits installation of vulnerable releases. The 7-day SLA for a CVE with an available patch expired 23 days ago.

**Remediation:** Bump the lower bound in `pyproject.toml` to `cryptography>=50.0.0` and re-lock. No API changes are needed.

### W-2 — confirm_email_change: email-change JWT not blacklisted after use (day 17)

**Tracking:** Issue #197  
**File:** `src/regstack/routers/account.py` — `confirm_email_change`  

`_decode_email_change_token` returns a `payload` but discards the `jti`. After `users.update_email(...)` succeeds the token is never inserted into `BlacklistRepo`. A replay attack within the token's TTL window can re-run `update_email` a second time, potentially triggering an unnecessary DB write and `tokens_invalidated_after` bump.

**Remediation:** Extract `jti` from the payload and call `blacklist.revoke(jti, exp)` after `update_email` succeeds, mirroring the logout pattern.

### W-3 — confirm_email_change: bulk-revoke cutoff not applied to the token itself (day 17)

**Tracking:** Issue #198  
**File:** `src/regstack/routers/account.py` — `confirm_email_change`  

`_decode_email_change_token` does not call `is_payload_bulk_revoked` before acting. If a user's `tokens_invalidated_after` has been bumped (e.g., by a concurrent `change-password`), a pre-bump email-change token can still be consumed. The window is narrow but the invariant is violated.

**Remediation:** After decoding the email-change token, fetch the user and call `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)`. If revoked, return 401.

### W-4 — OAuth _resolve_user: UserAlreadyExistsError not caught on concurrent new-user branch (day 17)

**Tracking:** Issue #199  
**File:** `src/regstack/routers/oauth.py` — `_resolve_user`  

In the new-user branch, `users.create()` can raise `UserAlreadyExistsError` if two OAuth callbacks arrive simultaneously for the same email address. This exception propagates unhandled → HTTP 500 instead of a safe 409 or a retry that resolves to the newly-created user.

**Remediation:** Wrap `users.create()` in a `try/except UserAlreadyExistsError` block; on conflict, fall through to `users.get_by_email()` and continue with the link step.

### W-6 — SQL oauth_states.consume() SELECT+DELETE not atomic (day 9)

**Tracking:** Issue #208  
**File:** `src/regstack/backends/sql/repositories/oauth_state_repo.py`  

The SQL backend's `consume()` implementation fetches the state row then deletes it in two separate statements without an explicit transaction or `RETURNING`-style atomic delete. Under concurrent load, two racing callbacks could both read the row before either deletes it, consuming the same state twice. This breaks the one-shot guarantee of the OAuth `state` parameter and the PKCE `code_verifier`.

**Remediation:** Use a single `DELETE ... RETURNING *` (Postgres/SQLite 3.35+) or wrap both statements in a `BEGIN`/`COMMIT` with a `SELECT FOR UPDATE` so only one callback can consume the row.

## 🟡 INFO

### I-1 — pyjwt `exp`/`iat` verification disabled by design

`JwtCodec` passes `verify_exp=False, verify_iat=False` to pyjwt and manually validates both claims against an injected `Clock`. This is intentional (enables `FrozenClock` in tests) and the manual checks are present and correct. No action needed; document in SECURITY.md if one is created.

### I-2 — `iat` emitted as float

`JwtCodec.encode` emits `iat` as `now.timestamp()` (a float). This is correct per the bulk-revoke design (microsecond precision prevents false revocations on same-second logins after a password change). Confirm no downstream consumers truncate to int before comparison.

### I-3 — `is_payload_bulk_revoked` uses `<=` not `<`

Conservative by design: a token minted at exactly the cutoff instant is revoked. Combined with float `iat` this is the right trade-off. No action needed.

### I-4 — Lockout short-circuits when `rate_limit_disabled=True`

`LockoutService.record_failure` and `.check` are no-ops when `rate_limit_disabled=True`. This flag must never be set in production configuration; it is test-only. No production config path sets it.

### I-5 — OAuth `_validate_redirect` screens backslashes and `//`

Present and correct. The check runs before the redirect URL is used. No open-redirect vector identified.

### I-6 — `error` param from OAuth provider sanitized before logging

`_sanitize_for_log` strips the provider-supplied `error` parameter before it reaches any log line. No log-injection vector identified.

### I-7 — PKCE `code_verifier` stored only on the state row, never in the URL

Correct. `code_challenge` (SHA-256 of `code_verifier`) goes to the provider URL; the raw verifier stays server-side. No PKCE downgrade vector identified.

### I-8 — MongoDB user_id inputs guarded by `ObjectId.is_valid`

All `user_id` parameters in Mongo repos are validated before use. No `$where`, `$expr`, or `$function` operators used. No injection vector identified.

### I-9 — All API input models use `extra="forbid"`

No unintended fields are accepted. No mass-assignment vector identified.

### I-10 — `UtcDateTime` TypeDecorator ensures tz-aware datetimes across SQL backends

`process_bind_param` and `process_result_value` both re-attach UTC when the value is naive. This prevents the `TypeError: can't compare offset-naive and offset-aware datetimes` that would silently break bulk-revoke comparisons on SQLite.

### I-12 — GitHub Actions SHA-pinned

`publish.yml` and `test.yml` both reference actions by full commit SHA (not mutable tags). No mutable-tag supply-chain vector identified.

### I-13 — OIDC trusted publishing; no `PYPI_API_TOKEN`

`publish.yml` uses `id-token: write` + `pypa/gh-action-pypi-publish` with `attestations: true`. No long-lived PyPI token in repo secrets. PEP 740 sigstore attestations are generated at build time.

### I-14 — `publish.yml` has no `workflow_dispatch` trigger

Tag-only publish prevents accidental or unauthorized manual publishes. Tag-vs-version mismatch checked via `tomllib` (not package import, so no import-time code execution).

### I-15 — Google JWKS fetch uses 5s timeout and `asyncio.to_thread`

`PyJWKClient(jwks_url, cache_keys=True, timeout=5)`. The synchronous fetch is offloaded via `asyncio.to_thread` to avoid blocking the event loop. No unbounded JWKS fetch identified.
