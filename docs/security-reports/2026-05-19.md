## 🟡 INFO (Best practice recommendations)

### I-1 · `sms.log_bodies` default asymmetry with `email.log_bodies`

**File:** `src/regstack/config/schema.py`, `SmsConfig`, line 101

**Observation:** `SmsConfig.log_bodies` defaults to `True`, logging the full SMS body
(including the 6-digit MFA code) at INFO level via the null backend. By contrast,
`EmailConfig.log_bodies` defaults to `False`, keeping email bodies at DEBUG level unless
explicitly opted in.

A developer who promotes a staging configuration that uses `backend = "null"` (the only
backend available without the `sns` or `twilio` extras) to a shared environment would
have OTP codes visible in INFO-level logs — potentially scraped by log-aggregation pipelines.

**Mitigations already in place:**

- The `log_bodies` field docstring says _"Set to False to silence code logging in shared
  environments."_
- SNS and Twilio backends ignore `log_bodies` entirely and never log message bodies.
- The null backend is labelled a development tool in the docs and all three example
  TOMLs use `backend = "null"` with an in-code comment explaining it's demo-only.

**Risk:** Low. This only affects deployments where the null backend is used outside its
intended development context.

**Remediation:** Consider adding an explicit warning to the config field's docstring that
`backend = "null"` should **never** be used in a production or shared-log environment,
or default `log_bodies = False` (matching `email.log_bodies`) with documentation that
developers running the flow locally should flip it on.

### §7 Session and token security

`JwtCodec` disables pyjwt's `exp`/`iat` checks and validates both against the injected
`Clock`. `FrozenClock`-driven tests remain deterministic; production correctness relies
on this seam.

`iat` emitted as a float (`self.iat.timestamp()` in `TokenPayload.to_claims()`).
Float-precision `iat` ensures a login completing microseconds after a bulk-revoke cutoff
has `iat > cutoff` and is not falsely revoked.

Every JWT carries a 16-byte URL-safe `jti` (`secrets.token_urlsafe(16)`) — per-token
blacklist (`BlacklistRepo`) works on every issued token.

JWT algorithm restricted to `Literal["HS256", "HS384", "HS512"]` in `config/schema.py`.

`AuthDependencies._authenticate` checks in order:
1. Bearer token present and scheme-valid → static 401 on `TokenError` (pyjwt diagnostic text not echoed).
2. `blacklist.is_revoked(jti)` → 401 if revoked.
3. `users.get_by_id(sub)` → 401 if user missing or `is_active=False`.
4. `is_payload_bulk_revoked(payload, tokens_invalidated_after)` → 401 if `iat ≤ cutoff`.

No token values appear in any `log.info`/`log.warning`/`log.error` call in the
authentication path.

`PyJWKClient(jwks_url, cache_keys=True)` — no explicit `timeout` parameter; pyjwt 2.12.1
(minimum and locked version) defaults `PyJWKClient.timeout = 30 s`. JWKS lookups time
out at most in 30 seconds.

### §14 OAuth subsystem

**§14a PKCE invariants:** `code_verifier` (64-byte URL-safe random) stored on the
`oauth_states` row; only `code_challenge` (SHA-256 with URL-safe base64, no padding) goes
to the provider URL. Confirmed in `_begin_flow()`, `routers/oauth.py:596–614`.

**§14b State row lifecycle:**
- Expiry checked against `rs.clock.now()` (not `datetime.now(UTC)`).
- SQL `consume()`: `SELECT` + `DELETE` inside `engine.begin()` — atomic.
- MongoDB: `find_one_and_delete` — atomic.
- Missing row or missing `result_token` → 404. Expired row → 400.
- Expiry re-checked **after** `consume()` in `/oauth/exchange`, so an expired row is
  still deleted (preventing replay) and returns 400 on the stale call.

**§14c ID-token verification:** `GoogleProvider.verify_id_token` validates JWKS signature
(`PyJWKClient`, `algorithms=["RS256"]`), `iss`, `aud == client_id`, `exp`, `iat`,
`nonce`. `require=["sub","iss","aud","exp","iat","nonce"]` enforced by pyjwt.
Nonce compared separately after decode. `OAuthIdTokenError` carries a generic outer
message; the diagnostic goes to `log.warning` only.

**§14d Linking-policy enforcement:**
- Default: existing email user → `?error=email_in_use`.
- `auto_link_verified_emails=True` AND `info.email_verified=True` both required for auto-link.
- Identity on a different user → `?error=identity_in_use`.
- Same identity re-linked → `?error=already_linked`.

**§14e OAuth-only user side effects:**
- `POST /login` with `hashed_password=None` → generic 401.
- `/change-password`, `/change-email`, `DELETE /account` → 400 via `require_password_set()`.
- `DELETE /oauth/{provider}/link` → 400 when user has no password and only one provider.

**§14f Identity-row uniqueness:**
- SQL: `UniqueConstraint("provider","subject_id")` and `UniqueConstraint("user_id","provider")`.
- Mongo: `provider_subject_unique` and `user_provider_unique` in `indexes.py`.

**§14g Hooks:** All four OAuth hooks (`oauth_signin_started`, `oauth_signin_completed`,
