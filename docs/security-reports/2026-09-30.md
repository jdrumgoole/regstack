## Section 1 — Dependency CVEs

### 🟠 W-12 — `pyjwt` floor below 2.14.0 — nine-CVE cluster (day 2 of SLA clock)

`pyproject.toml` declares `pyjwt>=2.13.0` in `dependencies` and `pyjwt[crypto]>=2.13.0` in `optional-dependencies.oauth` and `dev`. PyJWT 2.14.0 (released 2026-09-11) fixes a nine-CVE cluster. Two CVEs are directly on regstack's live code paths:

- **CVE-2026-102268 (CVSS 9.1 — CRITICAL severity class):** `is_pem_format` asymmetric/HMAC confusion allowing HMAC token forgery when an asymmetric public key is supplied as an HMAC secret. regstack's `JwtCodec` uses HS256 with purpose-derived HMAC keys only — no PEM involved; `GoogleProvider.verify_id_token` pins `algorithms=["RS256"]`. However, the deficient floor ships with every `pip install regstack` and is a supply-chain concern for any host that combines regstack with asymmetric JWT logic.
- **CVE-2026-102267 (CVSS 7.4 — HIGH):** `PyJWKClient` follows HTTP redirects without validation on the JWKS fetch. Directly on regstack's OAuth ID-token verification code path (`GoogleProvider.verify_id_token` → `self._jwks_client.get_signing_key_from_jwt`).

**Remediation:** Bump both floor entries to `pyjwt>=2.14.0` and `pyjwt[crypto]>=2.14.0` in `pyproject.toml`; run `uv lock`.

### 🟠 W-4 — Race condition: new OAuth user creation raises unhandled 500 (day 30 — **23 days past SLA**)

`src/regstack/routers/oauth.py` (`_resolve_user`): `await rs.users.create(new_user)` not wrapped in `try/except UserAlreadyExistsError`. Two concurrent requests with the same Google `sub` can both reach this line; the second raises an unhandled 500. **Still open. No change.**

**Remediation:** Wrap in `try/except UserAlreadyExistsError` and fall back to `rs.users.get_by_email(info.email)`.

### 🟠 W-6 — SQL `OAuthStateRepo.consume` non-atomic under READ COMMITTED (day 22 — **15 days past SLA**)

`src/regstack/backends/sql/repositories/oauth_state_repo.py`: Under PostgreSQL's default READ COMMITTED isolation level, two concurrent connections can both `SELECT` the state row before either commits the `DELETE`; both callers receive the state row and can exchange it for a session token. **Still open. No change.**

**Remediation:** Replace the SELECT + DELETE with a single `DELETE FROM oauth_states WHERE id = ? RETURNING *`, or add `with_for_update()` to the SELECT.

## Carry-forward Findings Not Separately Discussed Above

### 🟠 W-2 — Email-change token `jti` never blacklisted (day 30 — **23 days past SLA**)

`src/regstack/routers/account.py` `confirm_email_change`: after successfully decoding the email-change JWT and calling `users.update_email(...)`, the handler never calls `blacklist.revoke(jti, exp)`. A valid email-change link can be replayed until it expires (default 60-min TTL). **Still open. No change.**

**Remediation:** After `_decode_email_change_token(token)`, extract `jti`/`exp`, check `await rs.blacklist.is_revoked(jti)` → 400 if consumed, then call `await rs.blacklist.revoke(jti, exp)` on success.

### 🟠 W-3 — Email-change handler skips bulk-revocation check (day 30 — **23 days past SLA**)

`src/regstack/routers/account.py` `confirm_email_change`: after `_decode_email_change_token`, the handler fetches the user but never calls `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)`. A token minted before a `change-password` event would still be accepted, allowing a stolen email-change link to change a user's email even after the user has reset their password. **Still open. No change.**

**Remediation:** After `users.get_by_id(user_id)`, add a bulk-revoke check.

### 🟠 W-8 — Timing oracle distinguishes OAuth-only accounts on login (day 12 — **5 days past SLA**)

`src/regstack/routers/login.py`: when `user.hashed_password is None`, the short-circuit prevents the Argon2 `verify()` call. Login returns measurably faster for OAuth-only accounts than for accounts with an incorrect password, enabling timing-based enumeration of which accounts use OAuth-only sign-in. **Still open. No change.**

**Remediation:** Always call `rs.password_hasher.dummy_verify()` when `hashed_password is None` before raising the 401.
