### §3 — Authentication & Authorization Audit

Every endpoint that returns user data or mutates state requires `Depends(rs.deps.current_user())` or `Depends(rs.deps.current_admin())`. The sole unauthenticated mutation endpoint (`POST /confirm-email-change`) is authenticated via the purpose-scoped email-change JWT in the request body — not a session token. All user-facing responses use `UserPublic.from_user(...)`, which excludes `hashed_password`.

**Bulk-revoke discipline — confirmed present across all event types:**
- `POST /reset-password` → `users.update_password(...)` (bumps `tokens_invalidated_after` in both Mongo and SQL backends) + `lockout.clear(email)`. ✓
- `POST /change-password` → `users.update_password(...)` + `lockout.clear(...)`. ✓
- `POST /confirm-email-change` → `users.update_email(...)` (bumps `tokens_invalidated_after`) + `lockout.clear(previous_email)`. ✓
- `PATCH /admin/users/{id}` with `is_active=false` → `users.set_tokens_invalidated_after(user.id, rs.clock.now())` called immediately after `set_active`. ✓ (`routers/admin.py:112`)
- `DELETE /account` and `DELETE /admin/users/{id}` → `oauth_identities.delete_by_user_id(user.id)` before `users.delete(user.id)` — no orphaned identity rows. ✓

**OAuth-only users (`hashed_password=None`):** `POST /login` checks `user.hashed_password is None` and falls through to `record_failure` + the same generic 401 as a wrong-password attempt — no enumeration of OAuth-only status. `change-password`, `change-email`, `delete-account` invoke `require_password_set(user)` → HTTP 400 with forgot-password pointer. ✓

**Password comparison:** `rs.password_hasher.verify(plaintext, hash)` via `pwdlib` (Argon2id, constant-time). Never `==`. ✓

**JWT key isolation:** `derive_secret(jwt_secret, purpose)` — HMAC-SHA256 keyed on the purpose string. Session tokens cannot satisfy password-reset, email-change, phone-setup, or login-MFA endpoints. ✓

### §6 — Rate Limiting & DoS Prevention

- `LockoutService.check(payload.email)` is the first call in `POST /login`, before user lookup and password verification. A locked attacker cannot probe whether their guess is correct. ✓
- `lockout.record_failure` fires on: user not found, wrong password, `hashed_password is None`, correct-password-but-inactive, correct-password-but-unverified. Every branch that could yield account-state information also increments the counter. ✓
- Admin `GET /admin/users` pagination: `limit: Annotated[int, Query(ge=1, le=200)] = 50` — hard cap at 200. ✓
- MongoDB `login_attempts` has a TTL index sized to `config.login_lockout_window_seconds`. SQL backends filter by `when >= now - window` plus `purge_expired()`. ✓
- OAuth state rows: Mongo TTL index (`oauth_state_ttl`, `expireAfterSeconds=0` on `expires_at`). SQL exposes `purge_expired()`. Default TTL 5 minutes. No unbounded state accumulation. ✓
- No file-upload endpoints. ✓

### §7 — Session & Token Security

- JWT algorithm: HS256 (configurable to HS384/HS512). Secret validated `>= 32 chars` at `JwtCodec.__init__` — raises `ValueError` on short or empty secret, failing closed. ✓
- Every JWT includes `jti` (`secrets.token_urlsafe(16)` — 128 bits). Per-token blacklist revocation depends on this. ✓
- `iat` emitted as `float` (`now.timestamp()`) — a login completing microseconds after a bulk-revoke cutoff has `iat > cutoff` and is not falsely rejected. `exp` is `int` (precision immaterial for expiry). ✓
- `JwtCodec.decode` disables pyjwt's built-in `verify_exp`/`verify_iat`/`verify_nbf` and re-validates both against the injected `Clock`. Tests use `FrozenClock`; production uses `SystemClock`. ✓
- `_authenticate` gate order (confirmed): decode → 401 on `TokenError` (generic message); `blacklist.is_revoked(jti)` → 401; `users.get_by_id(sub)` + `is_active` check → 401; `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` → 401. ✓
- No `access_token`, `id_token`, or JWT values appear in `log.info`/`log.warning`/`log.error`. OAuth provider error strings are sanitized via `_sanitize_for_log` (CR/LF stripped, capped at 200 chars) before logging. ✓

### §14 — OAuth Subsystem Audit

**14a. PKCE invariants:** `_begin_flow` generates `code_verifier = secrets.token_urlsafe(64)` server-side and stores it on the `OAuthState` row. Only `code_challenge = base64url(sha256(code_verifier))` goes to the provider. The verifier never appears in any URL. ✓

**14b. State row lifecycle:** Missing row → `?error=bad_state`. Expired row → `?error=state_expired` (comparison uses `rs.clock.now()`, not `datetime.now(UTC)`). `oauth_states.consume(payload.id)` atomically reads and deletes the row — a second exchange returns `None` → 404. After a successful callback the row's expiry is shortened to `oauth.completion_ttl_seconds` (default 30 s), bounding the window during which a stolen state-id can yield a session token. ✓

**14c. ID-token verification:** `GoogleProvider.verify_id_token` validates signature against Google JWKS (`PyJWKClient` with `timeout=5`), checks `iss == GOOGLE_ISSUER`, `aud == client_id`, `exp`/`iat` via pyjwt, and `nonce` against `state_row.nonce`. `options={"require": ["sub", "iss", "aud", "exp", "iat", "nonce"]}` enforced. Any failure raises `OAuthIdTokenError`; the specific reason is logged at WARNING but never echoed in the redirect. ✓

**14d. Linking-policy enforcement:** Auto-link fires only when `oauth.auto_link_verified_emails=True` AND `info.email_verified=True`. Identity already on a different account → `?error=identity_in_use`. Relinking the same identity to the same account → `?error=already_linked`. ✓

**14e. OAuth-only user side effects:** `POST /login` returns the same generic 401 for `hashed_password=None` users. `change-password`, `change-email`, `delete-account` → `require_password_set(user)` → HTTP 400. `DELETE /oauth/{provider}/link` refuses if `not has_password and other_identities == 0`. ✓

**14f. Identity-row uniqueness:** Mongo: unique indexes on `(provider, subject_id)` and `(user_id, provider)` — confirmed in `backends/mongo/indexes.py`. SQL: matching `UniqueConstraint` declarations in `backends/sql/schema.py`. Parity confirmed. ✓

**14g. Hook events:** `oauth_signin_started`, `oauth_signin_completed`, `oauth_account_linked`, `oauth_account_unlinked` all present in `hooks/events.KNOWN_EVENTS` and fired at the correct points in `routers/oauth.py`. ✓

### §15 — Multi-backend Parity & Schema Migration Safety

**15a. CI matrix:** `test.yml` runs `pytest -n auto` across Python 3.11 and 3.12, with MongoDB (service container) and PostgreSQL (service container), SQLite inline, and SecantusDB embedding its own server per xdist worker. All four backends exercise the same parametrized suite on every push. ✓

**15b. Schema migration safety:** Three migrations — `0001_initial_schema.py`, `0002_oauth.py`, `0003_oauth_state_result_was_new.py`. All three have working `upgrade()` and `downgrade()` functions. `0002` uses `batch_alter_table` for the `hashed_password` nullability change (SQLite-safe). `0003` uses `batch_alter_table` for the `result_was_new` `ADD COLUMN` (SQLite-safe). ✓

**15c. Mongo index parity:** Every SQL `UniqueConstraint` has a matching Mongo unique index:
- `users.email` UNIQUE → `email_unique`. ✓
- `oauth_identities (provider, subject_id)` UNIQUE → `provider_subject_unique`. ✓
- `oauth_identities (user_id, provider)` UNIQUE → `user_provider_unique`. ✓
- TTL parity: all `expires_at`-bearing collections have Mongo TTL indexes (`expireAfterSeconds=0`). SQL backends expose `purge_expired()` with bound timestamp parameters. ✓

**15d. Datetime tz-awareness:** `make_client(tz_aware=True)` for Mongo. `UtcDateTime` TypeDecorator re-attaches UTC in `process_result_value` on every read from SQL. No naive-datetime path can reach the bulk-revoke comparison. ✓
