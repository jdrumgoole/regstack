## 🔴 CRITICAL (Immediate action required)

### C-1 — CVE-2026-48710 (BadHost): Starlette 1.0.0 locked — fix is 1.0.1

**Section:** §1 Dependency Vulnerability Check  
**File:** `uv.lock` / `pyproject.toml`

`uv.lock` resolves `starlette` to **1.0.0**, which is vulnerable to
[CVE-2026-48710 ("BadHost")](https://badhost.org/) — a Host-Header Auth
Bypass disclosed 21 May 2026 (OSTIF/encode) and fixed in Starlette 1.0.1.

**Technical summary:** Affected versions reconstruct `request.url` by
concatenating `http://{Host}{path}` and re-parsing the result. When the
`Host` header contains RFC-9112-invalid characters (e.g. `/`, `?`, `#`),
the re-parse shifts the path/query boundaries. Any middleware or endpoint
that gates security decisions on `request.url.path` — rather than the
ASGI-router-authoritative `request.scope["path"]` — can be bypassed with a
single malformed character in the `Host` header.

**Regstack's direct exposure:** Regstack's own auth is JWT-header based
(`HTTPBearer`), not path-based middleware, so the core auth stack is not
directly bypassable via this vector. However:

1. **regstack ships `fastapi` as a `dependencies` entry** and the lower bound
   `fastapi >= 0.120.0` does not guarantee Starlette ≥ 1.0.1 will be resolved
   by pip/uv on a fresh install — a host running `pip install regstack` may
   resolve Starlette 1.0.0 and remain vulnerable indefinitely.
2. **Host apps that add path-based security middleware** (rate limiting,
   tenant routing, IP allow-listing) using `request.url.path` are exposed by
   the transitive Starlette dependency regstack carries.
3. FastAPI's own `request.url_for` / OpenAPI schema generation are also
   affected, creating a supply-chain surface risk for every consumer of the
   regstack wheel.

**Recommended fix:**

```toml
# pyproject.toml
"fastapi>=0.120.0",   # current lower bound — does NOT guarantee Starlette 1.0.1
```

Two actions needed:

1. Determine which FastAPI version first ships with Starlette ≥ 1.0.1 as a
   dependency floor and raise the lower bound accordingly, OR add an explicit
   `starlette>=1.0.1` entry to `pyproject.toml` `dependencies`.
2. Run `uv lock --upgrade-package starlette` to resolve 1.0.1+ into
   `uv.lock` immediately so CI and future installs are protected.

**Mitigation for host apps (immediate):** Replace `request.url.path` with
`request.scope["path"]` in any security-sensitive middleware until the
Starlette version is bumped.

**References:**
- <https://badhost.org/>
- <https://ostif.org/disclosing-the-badhost-vulnerability-in-starlette/>
- <https://github.com/advisories/GHSA-86qp-5c8j-p5mr>

## 🟠 WARNING (Address within 1 week)

### W-1 — `jwt_secret` minimum length not enforced at the config layer

**Section:** §7 Session & Token Security  
**File:** `src/regstack/config/schema.py:290`, `src/regstack/auth/jwt.py:118`

The `RegStackConfig.jwt_secret` field validator at line 290 is a no-op
pass-through that returns `v` unchanged:

```python
@field_validator("jwt_secret")
@classmethod
def _warn_empty_secret(cls, v: SecretStr) -> SecretStr:
    # ... comment says validation lives at the façade boundary
    return v
```

`JwtCodec.__init__` rejects only the **empty string**:

```python
if not config.jwt_secret.get_secret_value():
    raise ValueError("RegStackConfig.jwt_secret is empty.")
```

A host that sets `jwt_secret = "x"` (a 1-character secret) passes both
checks and produces HS256 tokens signed with a trivially brute-forceable key.
RFC 7518 §3.2 requires HS256 keys to be at least 256 bits (32 bytes). Nothing
in regstack today enforces this floor, so a misconfigured deploy generates
valid-looking but cryptographically weak tokens.

**Recommended fix:** Add a minimum-length constraint on the field, consistent
with the prompt's stated invariant ("≥32 chars enforced at construction"):

```python
jwt_secret: Annotated[SecretStr, Field(
    default_factory=lambda: SecretStr(""),
    min_length=0,           # allow empty only so test fixtures opt out
)] = ...
```

Then enforce ≥ 32 chars in the validator rather than the no-op:

```python
@field_validator("jwt_secret")
@classmethod
def _check_secret_length(cls, v: SecretStr) -> SecretStr:
    raw = v.get_secret_value()
    if raw and len(raw) < 32:
        raise ValueError(
            "jwt_secret must be at least 32 characters for HS256 security. "
            "Run `regstack init` or set REGSTACK_JWT_SECRET to a value from "
            "`python -c 'import secrets; print(secrets.token_urlsafe(64))'`."
        )
    return v
```

This lets the empty-string default survive test fixture construction (where
JwtCodec raises at runtime anyway) while rejecting weak non-empty secrets
at config load time.
