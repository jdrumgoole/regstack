### §3 — Authentication & Authorization Audit

Every endpoint that returns user data or mutates user state requires either `Depends(rs.deps.current_user())` or `Depends(rs.deps.current_admin())`. Admin-only endpoints (`/admin/stats`, `/admin/users`, `/admin/users/{id}`, `/admin/users/{id}/resend-verification`, `/admin/pending/{email}/promote`) all use `current_admin()`.

All user data in responses goes through `UserPublic.from_user(...)`, which excludes `hashed_password`, `tokens_invalidated_after` (included intentionally — see §9), and internal Mongo `_id` alias.

**Bulk-revoke discipline — confirmed present:**
- `POST /reset-password` → `users.update_password(user_id, new_hash)` (which sets `tokens_invalidated_after = clock.now()` in both Mongo `UserRepo` and `SqlUserRepo`) + `lockout.clear(email)`. ✓
- `POST /change-password` → `users.update_password(...)` + `lockout.clear(...)`. ✓
- `POST /confirm-email-change` → `users.update_email(...)` (bumps `tokens_invalidated_after` in both backends) + `lockout.clear(previous_email)`. ✓ (endpoint is token-authenticated via the email-change JWT, intentionally requires no session cookie)
- `PATCH /admin/users/{id}` with `is_active=false` → `users.set_tokens_invalidated_after(user.id, rs.clock.now())` called immediately after `set_active`. ✓ (`routers/admin.py:112`)
- `DELETE /account` and `DELETE /admin/users/{id}` → `oauth_identities.delete_by_user_id(user.id)` before `users.delete(user.id)` to prevent orphaned identity rows. ✓

**OAuth-only users (`hashed_password=None`):** `POST /login` checks `user.hashed_password is None` and falls through to `record_failure` + same generic 401 as a wrong-password attempt — no enumeration of OAuth-only status. `change-password`, `change-email`, `delete-account` invoke `require_password_set(user)` which returns 400. ✓

**Password comparison:** `rs.password_hasher.verify(plaintext, hash)` via `pwdlib` (Argon2id constant-time). Never `==`. ✓

**JWT key isolation:** `derive_secret(jwt_secret, purpose)` — HMAC-SHA256 of master secret keyed on the purpose string. Session tokens cannot satisfy password-reset, email-change, phone-setup, or login-MFA verification. ✓

### §4 — Storage-layer Injection Safety

**MongoDB (`src/regstack/backends/mongo/repositories/`):**
- No `$where`, `$expr`, `$function`, or `$accumulator` operators. All query filters use Python dict literals with user-supplied values as document field values, never as operators.
- No user-input regex patterns (`re.compile`/`re.match` not present in backends).
- `UserRepo.get_by_id` and every `set_*`/`update_*` method guards with `ObjectId.is_valid(user_id)` before calling `ObjectId(user_id)` — malformed IDs return `None` or no-op rather than raising. ✓
- No unbounded `$in` arrays from user input.

**SQL (`src/regstack/backends/sql/repositories/`):**
- All queries use SQLAlchemy Core expression API with parameterised column comparisons (`self._t.c.email == email`, `where(self._t.c.id == user_id)`, etc.). No f-string or `%` interpolation into raw SQL.
- Two `text(...)` usages found: `text("SELECT 1")` (health-check ping, no user input) and `sa.text("SELECT COUNT(*) FROM users WHERE hashed_password IS NULL")` (migration downgrade guard, static string). Both safe.
- `UtcDateTime` TypeDecorator (`backends/sql/types.py`) consistently attaches UTC in both `process_bind_param` (write) and `process_result_value` (read). No path that could return a naive datetime to the bulk-revoke comparison. ✓
- `purge_expired()` methods across all SQL repos use bound timestamp parameters (SQLAlchemy `where(self._t.c.expires_at < cutoff)` with `cutoff` as a Python `datetime`). ✓

### §5 — Input Validation & Injection

- All API request bodies are typed Pydantic models with `ConfigDict(extra="forbid")`. No raw `dict` or untyped JSON body.
- Email fields use `EmailStr` validation throughout. `POST /admin/pending/{email}/promote` uses `email: str = Path(...)` — this is admin-only and passes the value only to a parameterised DB lookup; no injection risk. Minor consistency gap, but not a security issue given the authentication gate.
- Phone-number input goes through `is_valid_e164(payload.phone_number)` before storage in `POST /phone/start`. ✓
- Email Jinja2 templates use `autoescape=select_autoescape(["html"])` in `MailComposer`. No `| safe` filters or `{% autoescape false %}` in any email template under `src/regstack/email/templates/`.
- SSR templates under `src/regstack/ui/templates/` contain no `| safe` filters, no `{% autoescape false %}` blocks, and no auth-state variables (`{{ user.email }}` etc.) rendered server-side.
- `regstack init` CLI wizard writes config via `tomlkit` (non-destructive TOML merge). No user input is fed into shell commands.
- `redirect_to` query parameters on `GET /oauth/{provider}/start` and `POST /oauth/{provider}/link/start` are validated by `_validate_redirect`: rejects backslashes (browser normalization vector), protocol-relative URLs (`//host`), and off-origin full URLs against `config.base_url`. Returns HTTP 400 on violation. ✓

### §6 — Rate Limiting & DoS Prevention

- `LockoutService.check(payload.email)` is the first call in `POST /login`, before user lookup and password verification, so a locked attacker cannot probe whether their guess is right.
- `lockout.record_failure` fires on: user not found, wrong password, correct-password-but-inactive, correct-password-but-unverified. All branches increment the counter, preventing response-code enumeration.
- `GET /admin/users` pagination: `limit: Annotated[int, Query(ge=1, le=200)] = 50` — capped at 200. ✓
- MongoDB `login_attempts` has a TTL index sized to `config.login_lockout_window_seconds`. SQL backends filter by `when >= now - window` plus `purge_expired()` for cleanup.
- OAuth state rows: Mongo has a TTL index (`oauth_state_ttl`, `expireAfterSeconds=0` on `expires_at`). SQL backends expose `purge_expired()`. Default TTL is 5 minutes (`config.oauth.state_ttl_seconds`). ✓
- No file-upload endpoints introduced.
- Per-route `slowapi` rate limiting is available via the `rate_limit` extra — wired lazily when `*_rate_limit` config strings are set. Base install works without it.

### §7 — Session & Token Security

- JWT algorithm: HS256 by default. Secret validated `>= 32 chars` at `JwtCodec.__init__` — raises `ValueError` on short or empty secret, failing closed. ✓
- Every JWT includes `jti` (`secrets.token_urlsafe(16)` — 128 bits). Per-token blacklist revocation depends on it. ✓
- `iat` emitted as `float` (`now.timestamp()`) so a login completing microseconds after a bulk-revoke cutoff has `iat > cutoff` and is not falsely rejected. `exp` is `int` (precision immaterial for expiry). ✓
- `JwtCodec.decode` disables pyjwt's `verify_exp`/`verify_iat`/`verify_nbf` and re-validates both against the injected `Clock` — `FrozenClock` tests stay deterministic; production uses `SystemClock`. ✓
- `_authenticate` order: decode → 401 on `TokenError`; `blacklist.is_revoked(jti)` → 401; `users.get_by_id(sub)` + `is_active` check → 401; `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` → 401. All four gates present in documented order. ✓
- Token values (`access_token`, `id_token`) do not appear in `log.info`/`log.warning`/`log.error`. The Google provider's debug log (`log.debug`) shows only HTTP status code and response body (not the client secret or auth code). OAuth error parameters from the provider are sanitized via `_sanitize_for_log` before logging. ✓

### §9 — Data Exposure

- JWT decode errors → generic `"Invalid or expired token."` 401. The pyjwt exception text (which names the specific failure: "signature verification failed", "expired", etc.) is caught and discarded before the HTTP response is constructed. ✓

- JWT secret (`SecretStr`), OAuth `google_client_secret` (`SecretStr`), and SMTP `smtp_password` (`SecretStr`) do not appear in log statements in any backend or router. ✓

### §14 — OAuth Subsystem Audit

**14a. PKCE invariants:** `_begin_flow` generates `code_verifier = secrets.token_urlsafe(64)` server-side and stores it on the `OAuthState` row. Only `code_challenge = base64url(sha256(code_verifier))` appears in the provider authorization URL. The verifier never appears in the redirect URL or any browser-visible location. ✓

**14b. State row lifecycle:** Missing row → `?error=bad_state`. Expired row → `?error=state_expired` (comparison uses `rs.clock.now()`, not `datetime.now(UTC)`). `oauth_states.consume(payload.id)` in `POST /oauth/exchange` uses `find_one_and_delete` (Mongo) — atomic read-and-delete so a second exchange with the same ID returns `None` → 404. After a successful callback the state row's expiry is shortened to `oauth.completion_ttl_seconds` (default 30 s) to narrow the token-theft window. ✓

**14c. ID-token verification:** `GoogleProvider.verify_id_token` validates signature against Google JWKS (`PyJWKClient` with `timeout=5`), checks `iss == GOOGLE_ISSUER`, `aud == client_id`, `exp`/`iat` via pyjwt defaults, and `nonce` against `state_row.nonce`. Any failure raises `OAuthIdTokenError`; the specific reason is logged at WARNING but never echoed in the redirect. ✓

**14d. Linking-policy enforcement:** Auto-link fires only when `oauth.auto_link_verified_emails=True` AND `info.email_verified=True`. Identity already on a different account → `?error=identity_in_use`. Relinking the same identity to the same account → `?error=already_linked`. `allow_registration=False` is checked before creating new-account OAuth users. ✓

**14e. OAuth-only user side effects:** `POST /login` returns the same generic 401 for `hashed_password=None` users as for wrong-password attempts — no account existence enumeration. `change-password`, `change-email`, `delete-account` call `require_password_set(user)` → HTTP 400. `DELETE /oauth/{provider}/link` refuses if `not has_password and other_identities == 0`. ✓

**14f. Identity-row uniqueness:** Mongo: unique indexes on `(provider, subject_id)` (`provider_subject_unique`) and `(user_id, provider)` (`user_provider_unique`) — confirmed in `backends/mongo/indexes.py:72–86`. SQL: matching `UniqueConstraint` declarations in `backends/sql/schema.py:143–144`. Parity confirmed. ✓

**14g. Hook events:** `oauth_signin_started`, `oauth_signin_completed`, `oauth_account_linked`, `oauth_account_unlinked` all present in `hooks/events.KNOWN_EVENTS`. Router fires them at the correct call sites in `oauth_start`, `oauth_callback`, and `oauth_unlink`. ✓

All three have `upgrade()` and `downgrade()`. `0002` uses `batch_alter_table` for the `hashed_password` nullability change (SQLite-safe). `0003` uses `batch_alter_table` for the `result_was_new` `ADD COLUMN` (SQLite-safe). `0002.downgrade()` has a null-count pre-check guard. ✓
