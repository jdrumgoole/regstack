advisories. CVE-2026-45447 remains the highest-severity open item for this
package.

### W-4 — CVE-2026-53533: `aiosmtplib 5.1.0` SMTP command injection (CVSS 6.5 Moderate) — carry-forward (day 13)

**Package:** `aiosmtplib` (base dependency: `aiosmtplib>=3.0`)
**Resolved (lock):** `5.1.0` · **Safe version:** `>=5.1.1`
**Advisory:** GHSA-v3q9-hj7j-63hq · Published: June 15, 2026
**Tracked:** GitHub issue #124

The locked version (`5.1.0`) **is** the vulnerable version. `5.1.1` rejects C0
control characters (CR, LF, NUL, etc.) in SMTP command arguments. Prior versions
accept them, allowing SMTP injection via a crafted email address such as
`attacker@evil.com\r\nBcc: victim@example.com`, which can silently add blind-copy
recipients to verification, password-reset, or MFA emails. This is directly on
regstack's security-critical email delivery paths.

CVE search for the 2026-07-05 to 2026-07-08 window found no new aiosmtplib
advisories beyond CVE-2026-53533.

**Action required:**
1. Bump `"aiosmtplib>=5.1.1"` in `pyproject.toml` with updated CVE comment.
2. Run `uv lock`.

**Resolved (lock):** `2.14.0` · **Safe version:** `>=2.14.2`

**Tracked:** GitHub issue #125

**Update from last review:** The vulnerability was previously tracked under the
provisional identifier "DailyCVE DC-Jun2026-536" (CVE-2026-32690). On

(`2.12.0`–`2.14.1`) and fix version (`>=2.14.2`) are unchanged.

The locked version (`2.14.0`) is in the vulnerable range. When a `BaseSettings`

the target file and exposes it as a config value. `RegStackConfig` extends
`BaseSettings` and reads from `secrets_env_path` (`regstack.secrets.env`).

**Action required:**

## 🟡 INFO (Best practice recommendations)

### I-1 — `UserPublic` exposes `tokens_invalidated_after` and `phone_number` (carry-forward)

`UserPublic` exposes `tokens_invalidated_after` (intentional — allows SPA clients to
detect bulk-revocation without an extra round-trip) and `phone_number` (design
decision). Hosts with stricter PII requirements should subclass `UserPublic` or add
a projection step. No code change required in regstack itself.

### I-2 — `admin_promote_pending` path parameter not validated as `EmailStr` (carry-forward)

`POST /admin/pending/{email}/promote` (`src/regstack/routers/admin.py:204`) accepts
`email: str = Path(...)`. A syntactically invalid email address passes parameter
binding and returns a 404 (LookupError path). The endpoint is admin-gated so the
risk is low. Fix is a one-liner: `email: Annotated[EmailStr, Path(...)]`.

### I-3 — Duplicate tracking issue for python-multipart cluster (carry-forward, day 12)

Issues #118 (2026-06-23) and #120 (2026-06-24) both track the python-multipart
floor bump. Issue #120 should be updated to enumerate all four CVEs
(CVE-2026-53537/53538/53539/53540) and set the required floor to `>=0.0.32`;
issue #118 should then be closed as a duplicate.
