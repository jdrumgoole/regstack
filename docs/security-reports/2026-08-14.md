## 🟠 WARNING

### W-1 (carry-over, day 3): `cryptography` floor ≥48.0.1 misses CVE-2026-69247

- **Files:** `pyproject.toml` lines 108 (oauth extra) and 154 (dev extra)
- **Locked version:** 49.0.0
- **Fixed version:** 50.0.0 (released 2026-07-31)
- **CVE:** CVE-2026-69247 — PKCS7 decrypt Bleichenbacher oracle in `pkcs7_decrypt_der`/`pem`/`smime`.
- **Impact:** regstack does not call PKCS7 decrypt directly, but (a) `pip install regstack[oauth]` resolves to a version with an open advisory, and (b) host apps sharing the virtualenv inherit the exposure.
- **Fix:** Bump both `[project.optional-dependencies].oauth` and `[dependency-groups].dev` in `pyproject.toml` to `cryptography>=50.0.0`, then run `uv lock`.
- **Tracking:** GitHub Issue #172 (open, no activity since first flagged 2026-08-12). **Deadline: 2026-08-18.**

## 🟡 INFO

### I-1: `tokens_invalidated_after` included in `UserPublic` API responses (intentional)

- **File:** `src/regstack/models/user.py:105–108`
- **Detail:** `UserPublic` includes `tokens_invalidated_after`. The inline docstring documents the design intent: SPAs comparing this field to their session JWT's `iat` can detect server-side revocation without an extra round-trip. The field reveals when the last password/email change occurred — low-sensitivity metadata. No action recommended unless future privacy requirements tighten.

### I-2: CLI `cmd:` log-source passes operator input to shell (intentional)

- **File:** `src/regstack/cli/validate/logtail.py:106`
- **Code:** `argv = ["sh", "-c", target]` where `target` is the operator-supplied value after `cmd:`.
- **Detail:** This is an operator-facing tool documented as accepting arbitrary shell commands. Runs only on operator workstations under operator credentials. No HTTP endpoint reaches this path. Design is intentional. **Note:** if ever exposed to untrusted input, the `cmd:` variant must be removed or sandboxed.

### I-3: PyJWT pinned at exact minimum with no headroom

- **File:** `pyproject.toml` line 55 — `pyjwt>=2.13.0`
- **Detail:** `pyjwt>=2.13.0` is simultaneously the floor and the latest upstream release. One new pyjwt advisory makes this floor insufficient with no buffer. Monitor weekly; bump floor promptly on any new release.

### §3 — Authentication & Authorization Audit

- All protected endpoints inject `Depends(rs.deps.current_user())` or `Depends(rs.deps.current_admin())`.
- Unauthenticated endpoints are exactly those that should be: register, login, verify, forgot-password, reset-password, resend-verification, oauth start/callback, confirm-email-change (token in body is the auth).
- **Bulk-revoke discipline verified on all five flows:**
  - Password reset → `users.update_password` (bumps `tokens_invalidated_after`) + `lockout.clear`.
  - Password change → same `users.update_password` path.
  - Email-change confirm → `users.update_email` (bumps `tokens_invalidated_after`).
  - Admin disable → `rs.users.set_tokens_invalidated_after(user.id, rs.clock.now())`.
  - Account deletion → `rs.oauth_identities.delete_by_user_id` before `rs.users.delete` (no orphan identity rows).
- All API responses use `UserPublic.from_user()` — `hashed_password` excluded throughout.
- OAuth-only users (`hashed_password=None`): `POST /login` returns the same generic 401 as a wrong-password attempt. `require_password_set()` gates change-password, change-email, delete-account with a 400 pointing at forgot-password.
- Constant-time comparison via `pwdlib.PasswordHash` (Argon2id) — never `==`.

### §4 — Storage-layer Injection Safety

- **MongoDB:** No `$where`, `$expr`, `$function`, or `$accumulator` operators in any query. No regex built from user input. `UserRepo.get_by_id` guards with `ObjectId.is_valid(user_id)` before conversion at all write operations.
- **SQL:** All queries use SQLAlchemy Core expression API with parameterized binds. Two `text()` calls exist (`text("SELECT 1")` health ping and a migration pre-check) — both safe with no user input. `UtcDateTime` TypeDecorator correctly reattaches UTC tzinfo on read. `purge_expired()` implementations use bound parameters.

### §6 — Rate Limiting & DoS Prevention

- Admin user listing capped: `Annotated[int, Query(ge=1, le=200)]` with default 50.
- OAuth state rows: Mongo TTL index on `expires_at` (`expireAfterSeconds=0`). SQL accumulation prevented by state row consumption at callback.
- No file-upload endpoints.

### §7 — Session & Token Security

- HS256 default; `len(raw) < 32` enforced at `JwtCodec.__init__`.
- `jti` required via `"require": ["sub", "exp", "iat", "jti", "purpose"]` at decode. All manual JWT construction paths include `jti: secrets.token_urlsafe(16)`.
- `iat` emitted as float (`self.iat.timestamp()` at `jwt.py:69`) — microsecond precision preserved for bulk-revoke safety.
- pyjwt `exp`/`iat` checks disabled in JwtCodec; re-validated against injected Clock. Same pattern in all custom token decode paths.
- `AuthDependencies._authenticate` five-gate revocation chain present: (1) Bearer scheme → 401; (2) JWT decode → generic 401; (3) `blacklist.is_revoked(jti)` → 401; (4) user lookup + `is_active` → 401; (5) `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` → 401.
- No token values logged anywhere.
- Per-purpose key derivation via HMAC-SHA256 for all five purposes: `session`, `email_change`, `login_mfa`, `phone_setup`, `password_reset`.

### §14 — OAuth Subsystem Audit

- **PKCE:** `code_verifier` stored server-side on state row; only SHA-256 challenge sent to provider. Verifier never appears in any URL.
- **State row lifecycle:** Missing row → `?error=bad_state`. Expiry compared against `rs.clock.now()`. Atomic consume: Mongo uses `find_one_and_delete`; SQL wraps read+delete in a single `engine.begin()` transaction.
- **ID-token verification:** signature (via PyJWKClient), `iss`, `aud`, `exp` (pyjwt default), `nonce` (manual check). All required claims enforced.
- **Auto-link policy:** Defaults `False`; fires only on `email_verified=True` when enabled. Identity in-use and already-linked cases detected and returned as 409.
- **Identity-row uniqueness:** `(provider, subject_id)` and `(user_id, provider)` unique at DB level in both Mongo indexes and SQL schema.
- **OAuth-only user side effects:** Generic 401 on password login; `require_password_set()` guards all password-confirmation flows; `DELETE /oauth/{provider}/link` refuses with 400 when no password and no other providers.
