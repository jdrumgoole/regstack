### §3 — Authentication & Authorization Audit

- Every endpoint that touches user state or returns user data requires `Depends(rs.deps.current_user())` or `Depends(rs.deps.current_admin())`. All admin endpoints use `current_admin()`.
- All user data returns are through `UserPublic.from_user(...)` which excludes `hashed_password`.
- **Bulk-revoke discipline:**
  - `reset-password` → `users.update_password(...)` (which bumps `tokens_invalidated_after`) + `lockout.clear()` + blacklists the reset token's `jti`. ✓
  - `change-password` → `users.update_password(...)` + `lockout.clear()`. ✓
  - `confirm-email-change` → `users.update_email(...)` (bumps `tokens_invalidated_after` in both SQL and Mongo repos). ✓
  - `PATCH /admin/users/{id}` with `is_active=false` → `users.set_tokens_invalidated_after(user.id, rs.clock.now())`. ✓
  - `DELETE /account` and `DELETE /admin/users/{id}` → cascade `oauth_identities.delete_by_user_id(...)` before `users.delete(...)`. ✓
- OAuth-only users (`hashed_password=None`) receive the same generic 401 on `POST /login` as wrong-password attempts (no account enumeration). `change-password`, `change-email`, `delete-account` invoke `require_password_set()` which returns 400 pointing at password-reset.
- Password verification uses `pwdlib.PasswordHasher.verify(...)` (Argon2id constant-time comparison), not `==`.
- JWT keys are per-purpose via `derive_secret(master, purpose)` (HMAC-SHA256). Session tokens cannot satisfy password-reset, email-change, phone-setup, or login-MFA endpoints.

### §4 — Storage-layer Injection Safety

**MongoDB:** No `$where`, `$expr`, `$function`, or `$accumulator` operators anywhere in `src/regstack/backends/mongo/`. No user-input regex patterns. `UserRepo` guards every `get_by_id`, `set_*`, `update_*` operation with `ObjectId.is_valid(user_id)` before constructing the filter. `OAuthIdentityRepo` and `PendingRepo` handle the `_id` conversion via `isinstance(doc.get("_id"), ObjectId)` on the read path. No unbounded `$in` from user input.

**SQL (SQLite + Postgres):** All queries use SQLAlchemy Core expression API with parameterised binds. Two `text(...)` usages are hardcoded strings (`"SELECT 1"` health-check, `"SELECT COUNT(*) FROM users WHERE hashed_password IS NULL"` in a migration data check) — neither interpolates user input. `UtcDateTime` TypeDecorator consistently re-attaches `UTC` tzinfo on `process_result_value`, preventing tz-naive datetimes from reaching the bulk-revoke comparison.

### §5 — Input Validation & Injection

- All API endpoints accept typed Pydantic models with `extra="forbid"` on request bodies. No raw `dict` or untyped JSON body.
- Email fields use `EmailStr` validation consistently.
- Phone-number inputs go through E.164 validation before storage.
- Jinja2 is configured with autoescape on for HTML email templates. No `| safe` or `{% autoescape false %}` in any SSR template under `src/regstack/ui/templates/`.
- SSR templates (`base.html`, login, register, forgot, reset, verify, me, mfa-confirm, oauth-complete) contain no `{{ user.email }}` or other auth-state data — they are stateless; state lives in `localStorage` via `regstack.js`.
- `redirect_to` query parameters on `/oauth/{provider}/start` and `/oauth/{provider}/link/start` are validated by `_validate_redirect`: rejects backslashes, protocol-relative URLs (`//host`), and off-origin full URLs. Returns 400 on any violation.
- No CLI wizard feeds user input into shell commands.

### §6 — Rate Limiting & DoS Prevention

- `LockoutService.check()` is the first thing in `POST /login`, before user lookup and password verification, so a locked account can't be probed.
- `record_failure` is called on missing user, wrong password, correct-password-but-inactive, and correct-password-but-unverified branches, preventing probing by response-code differentiation.
- `POST /admin/users` paginates with `limit: Annotated[int, Query(ge=1, le=200)] = 50` — capped at 200.
- MongoDB login_attempts collection has a TTL index sized to `login_lockout_window_seconds`.
- OAuth state rows have a TTL index (`expires_at`, `expireAfterSeconds=0`) on Mongo; SQL backends use `purge_expired()`.
- No file-upload endpoints exist.

### §7 — Session & Token Security

- JWT algorithm is HS256, secret is validated to ≥ 32 chars at `JwtCodec.__init__` (raises `ValueError` on short/empty secret).
- Every JWT includes a `jti` (`secrets.token_urlsafe(16)`). Per-token revocation via `BlacklistRepo` depends on it.
- `iat` is emitted as a float (`now.timestamp()` → `float`) in `TokenPayload.to_claims`. The `exp` is `int`, which is fine (the bulk-revoke comparison uses `iat`, not `exp`). Float `iat` ensures a login completing microseconds after a password change has `iat > cutoff` and isn't falsely revoked.
- `JwtCodec.decode` disables pyjwt's `verify_exp`/`verify_iat`/`verify_nbf` and re-validates both against the injected `Clock`. `FrozenClock` tests stay deterministic.
- `_authenticate` in `AuthDependencies` checks: decode → 401 on `TokenError`; blacklist `jti` → 401; user active → 401; bulk-revoke cutoff → 401. All in the documented order.
- No `access_token`, `id_token`, or `client_secret` values appear in `log.info`/`log.warning`/`log.error` calls. The Google provider's debug log shows only HTTP status and response body (never the client_secret or auth code). The OAuth callback sanitizes the provider-controlled `error` parameter before logging (`_sanitize_for_log`).

### §9 — Data Exposure

- All API responses return `UserPublic` (excludes `hashed_password`). The `tokens_invalidated_after` field is intentionally included in `UserPublic` so SPAs can detect session invalidation client-side without a round-trip — this is a documented design decision.

- OAuth callback failures → `?error=<short_code>` redirect, never the underlying exception.

### §14 — OAuth Subsystem Audit

**14a. PKCE:** `code_verifier` is generated server-side (`_secrets.token_urlsafe(64)`) and stored on the `oauth_states` row. `code_challenge` (SHA-256 of verifier, base64url-encoded) is the only value sent to the provider URL. Verifier never appears in the redirect URL or browser. ✓

**14b. State row lifecycle:** Missing row → `bad_state` redirect. Expired row → `state_expired` redirect (comparison uses `rs.clock.now()`). `oauth_states.consume(payload.id)` in `POST /oauth/exchange` atomically reads and deletes — a second exchange with the same id returns 404. State rows shortened to `oauth.completion_ttl_seconds` after a successful callback (narrowing the theft window). ✓

**14c. ID-token verification:** `GoogleProvider.verify_id_token` validates signature against Google JWKS (via `PyJWKClient`), `iss` matches configured issuer, `aud` matches `client_id`, `exp`/`iat` via pyjwt's default checks, and `nonce` matches `state_row.nonce`. Any failure raises `OAuthIdTokenError` with a generic outer message; the specific reason is logged (WARNING level) but never echoed to the redirect. ✓

**14d. Linking-policy enforcement:** Auto-link only when `oauth.auto_link_verified_emails=True` AND `info.email_verified=True`. Identity already linked to a different user → `identity_in_use`. Relinking the same identity to the same user → `already_linked`. `allow_registration=False` is respected on the new-account path. ✓

**14e. OAuth-only user side effects:** `POST /login` returns same generic 401 for `hashed_password=None` as for wrong password. `change-password`, `change-email`, `delete-account` call `require_password_set()` → 400. `DELETE /oauth/{provider}/link` checks `has_password or other_identities > 0` before allowing unlink. ✓

**14f. Identity-row uniqueness:** Mongo indexes: `(provider, subject_id)` unique (`provider_subject_unique`), `(user_id, provider)` unique (`user_provider_unique`). SQL schema mirrors both as `UniqueConstraint`. ✓

**14g. Hooks:** `oauth_signin_started`, `oauth_signin_completed`, `oauth_account_linked`, `oauth_account_unlinked` all present in `KNOWN_EVENTS`. Fired at the correct points in the callback and unlink endpoints. ✓

### §15 — Multi-backend Parity & Schema Migration Safety

**15a. CI matrix:** `test.yml` runs `pytest -n auto` against a matrix of Python 3.11 and 3.12, with MongoDB (Docker service) and Postgres (Docker service) wired via `REGSTACK_TEST_POSTGRES_URL`. SecantusDB embeds its own server per xdist worker (no service container needed). All four backends (SQLite, Postgres, MongoDB, SecantusDB) are covered on every push. ✓

**15b. Schema migrations:** `src/regstack/backends/sql/migrations/versions/` has `0001_initial_schema.py` and `0002_oauth.py`. Both have `upgrade()` and `downgrade()`. `0002_oauth.py` uses `batch_alter_table` for SQLite compatibility. ✓

**15c. Mongo index parity:**
- `users.email` UNIQUE → `email_unique` index. ✓
- `oauth_identities (provider, subject_id)` UNIQUE → `provider_subject_unique`. ✓
- `oauth_identities (user_id, provider)` UNIQUE → `user_provider_unique`. ✓
- TTL parity: every collection with `expires_at` has a Mongo TTL index (`expireAfterSeconds=0`). SQL backends use `purge_expired()` as documented. ✓

**15d. Datetime tz-awareness:** Mongo client built with `tz_aware=True`. SQL backend uses `UtcDateTime` TypeDecorator which re-attaches UTC in `process_result_value`. No naive-datetime path reaching the bulk-revoke comparison. ✓
