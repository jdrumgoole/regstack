### §3 — Authentication & Authorization Audit

✅ Clean

**Mounted routers:** `build_router(rs)` in `routers/__init__.py` wires the
composite router. Always-on: `register`, `verify`, `login`, `logout`,
`account`. Conditionally: `password` (when `enable_password_reset`),
`phone` + MFA (when `enable_sms_2fa`), `admin` (when
`enable_admin_router`), `oauth` (when `enable_oauth` AND at least one
provider registered). Every conditional mount is gated on the correct flag.

**Auth dependency injection:** Reviewed all router files. Every endpoint
that reads or mutates user-owned state injects `rs.deps.current_user()` or
`rs.deps.current_admin()` via `Depends(...)`. No endpoint that returns user
data bypasses this chain. `GET /me`, `PATCH /me`, `POST /change-password`,
`POST /change-email`, `POST /confirm-email-change`, `DELETE /account`,
`GET /admin/*`, `PATCH /admin/users/{id}`, `DELETE /admin/users/{id}`,
`POST /admin/users/{id}/resend-verification`, `POST /admin/pending/{email}/promote`,
`GET /oauth/providers`, `POST /oauth/{provider}/link/start`,
`DELETE /oauth/{provider}/link` — all authenticated. ✅

**Bulk-revoke discipline:**
- Password reset (`POST /reset-password`): `users.update_password()` bumps
  `tokens_invalidated_after` at the repo level. ✅
- Password change (`POST /change-password`): same path. ✅
- Email-change confirm (`POST /confirm-email-change`): `users.update_email()`
  bumps `tokens_invalidated_after`. ✅
- Admin disable (`PATCH /admin/users/{id}` with `is_active=False`):
  `users.set_active()` followed by explicit
  `users.set_tokens_invalidated_after(user.id, rs.clock.now())`. ✅
- Account deletion (`DELETE /account`): cascades
  `oauth_identities.delete_by_user_id(user.id)` before `users.delete()`.
  Same ordering in admin `DELETE /admin/users/{id}`. No orphan identity
  rows. ✅

**OAuth-only user (`hashed_password=None`) handling:**
- `POST /login` (`login.py:99`): `if user.hashed_password is None or not
  rs.password_hasher.verify(...)` — same generic 401 as wrong-password. ✅
- `POST /change-password`, `POST /change-email`, `DELETE /account`:
  guarded by `require_password_set(user)` helper → 400 with
  forgot-password pointer. ✅
- `DELETE /oauth/{provider}/link`: `has_password` and linked-identity count
  checked; refuses if only sign-in method. ✅

**Constant-time comparison:** password verification delegates to
`pwdlib.PasswordHasher.verify()` (Argon2). No `==` comparison of password
material in any router. ✅

**Per-purpose JWT keys:** `JwtCodec._key(purpose)` calls
`derive_secret(master, purpose)` (HMAC-SHA256). Confirmed in
`src/regstack/auth/jwt.py` and `src/regstack/config/secrets.py`. Compromise
of one purpose key does not compromise others. ✅

### §6 — Rate Limiting & DoS Prevention

✅ Clean

**Login lockout order:** `rs.lockout.check(payload.email)` executes at
`login.py:73` — before user lookup and password verification. A locked-out
account returns 429 with `Retry-After` regardless of password correctness.
No oracle for correct-password-but-locked. ✅

`expireAfterSeconds=config.login_lockout_window_seconds`. ✅

exposes `purge_expired()` for host-scheduled cleanup. ✅

(`expireAfterSeconds=0`). SQL backend exposes `purge_expired()`. ✅

**File uploads:** No user-facing file upload endpoints exist. ✅

### §7 — Session & Token Security

✅ Clean

**JWT configuration:** HS256 algorithm. `JwtCodec.__init__` enforces
`len(raw) >= MIN_JWT_SECRET_LENGTH` (32 chars) — raises `ValueError` on
shorter secrets. ✅

**Float `iat`:** `TokenPayload.to_claims()` emits
`"iat": self.iat.timestamp()` — Python `.timestamp()` returns a float.
Bulk-revoke comparison `payload.iat <= cutoff` is sub-second precise. ✅

**pyjwt exp/iat disabled:** `JwtCodec.decode` sets
`options={"verify_exp": False, "verify_iat": False, "verify_nbf": False}`
and re-validates both against the injected `Clock`. `FrozenClock`-driven
tests work correctly. ✅

**Required claims:** `options={"require": ["sub", "exp", "iat", "jti",
"purpose"]}` — every token carries `jti` for per-token revocation. ✅

**`_authenticate` chain** (verified in
`src/regstack/auth/dependencies.py`):
1. Decode token → static `"Invalid or expired token."` 401 on `TokenError`.
   pyjwt internal reason never echoed to client. ✅
2. `blacklist.is_revoked(payload.jti)` → 401 if revoked. ✅
3. `users.get_by_id(payload.sub)` + `user.is_active` check → 401 if not
   found or inactive. ✅
4. `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` → 401
   if `iat <= cutoff`. ✅

**Token logging:** Log statements in `src/regstack/routers/oauth.py` at
lines 315 and 318 log the `OAuthTokenExchangeError` /
`OAuthIdTokenError` exception messages (`"oauth token exchange failed: %s"`,
`"oauth id token verification failed: %s"`). These are generic wrapper
messages (e.g. `"HTTP 400 from Google"`, `"Signature verification failed"`);
no JWT body, no raw tokens, and no secrets appear in the logged string. ✅

### §14 — OAuth Subsystem Audit

✅ Clean

**14a — PKCE invariants:** `_begin_flow()` generates `code_verifier`
server-side (`secrets.token_urlsafe(64)`), computes the SHA-256
`code_challenge`, and stores the verifier on the `oauth_states` row.
Only `code_challenge` (not the verifier) appears in the authorization URL
sent to the provider. Raw verifier never leaves the server. ✅

**14b — State row lifecycle:**
- Missing row → `oauth_states.consume()` returns `None` → 404. ✅
- Expired row → `state_row.expires_at < rs.clock.now()` (uses injected
  clock, not `datetime.now(UTC)`). ✅
- `oauth_states.consume(id)` is atomic read-then-delete — a second
  exchange with the same `id` returns `None` → 404. ✅

**14c — ID-token verification:** `GoogleProvider.verify_id_token`
validates: RS256 signature via JWKS, `iss` against configured issuer,
`aud` against `client_id`, `exp` and `iat` validated by pyjwt, `nonce`
compared after decode. Any failure → `OAuthIdTokenError` with generic outer
message; specific pyjwt reason logged at WARNING server-side only. ✅

**14d — Linking-policy enforcement:**
- Existing email account + no auto-link → `?error=email_in_use`. ✅
- Identity already linked to different user → `?error=identity_in_use`. ✅
- Re-linking same identity to same user → `?error=already_linked`. ✅
- `auto_link_verified_emails=True` gates on `info.email_verified` from
  ID token. ✅

**14e — OAuth-only user side effects:**
- `POST /login` returns same generic 401 for `hashed_password=None`
  users — no enumeration. ✅
- `POST /change-password`, `POST /change-email`, `DELETE /account`:
  guarded by `require_password_set()` → 400. ✅
- `DELETE /oauth/{provider}/link`: refuses if last sign-in method. ✅

**14f — Identity-row uniqueness:**
- Mongo: `provider_subject_unique` and `user_provider_unique` unique
  indexes in `install_indexes()`. ✅
- SQL: `UniqueConstraint("provider", "subject_id", ...)` and
  `UniqueConstraint("user_id", "provider", ...)` in `schema.py`. Both
  backends enforce at DB level. ✅

**14g — Hooks:** `oauth_signin_started`, `oauth_signin_completed`,
`oauth_account_linked`, `oauth_account_unlinked` confirmed in

with MongoDB 7 and Postgres 16 service containers. `uv sync --extra dev`

**15b — Migration safety:** All three SQL migrations have both `upgrade()`
and `downgrade()`:

  them. ✅
- `0002_oauth.py` — adds `oauth_identities`, `oauth_states`; makes
  `users.hashed_password` nullable using `batch_alter_table` (SQLite
  compatible). Downgrade reverses both. ✅
- `0003_oauth_state_result_was_new.py` — adds `result_was_new` column via
  `batch_alter_table`. Downgrade removes it. ✅
