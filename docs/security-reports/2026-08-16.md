## 🟠 WARNING

### W-1 (carry-over, day 5, deadline in 2 days): `cryptography` floor ≥48.0.1 misses CVE-2026-69247

- **Files:** `pyproject.toml` lines 108 (oauth extra) and 154 (dev extra)
- **Locked version:** 49.0.0 (unchanged since first flagged 2026-08-11)
- **Fixed version:** 50.0.0 (released 2026-07-31; available for 16 days)
- **CVE:** CVE-2026-69247 — PKCS7 EnvelopedData decryption exposes a Bleichenbacher
  oracle through distinguishable errors and timing in `pkcs7_decrypt_der`,
  `pkcs7_decrypt_pem`, and `pkcs7_decrypt_smime`. Affects cryptography 44.0.0–49.x.
- **Impact:** regstack does not call PKCS7 decrypt directly (it uses `cryptography`
  only for JWKS-backed JWT signature verification via `pyjwt[crypto]`). However:
  (1) `pip install regstack[oauth]` resolves to 49.0.0, missing the fix;
  (2) any host using `cryptography` for PKCS7 operations in the same virtualenv
  inherits the exposure; (3) consumers auditing transitive dependencies will see
  an open advisory on a regstack transitive dependency.
- **Fix:**
  ```toml
  # pyproject.toml — oauth extra
  oauth = ["pyjwt[crypto]>=2.13.0", "cryptography>=50.0.0", "httpx>=0.27"]
  # pyproject.toml — dev extra
  "cryptography>=50.0.0",
  ```
  Update the comment block at lines 98–107 to document CVE-2026-69247 alongside
  the prior CVEs, then run `uv lock`.
- **Tracking:** GitHub Issue #172 (opened 2026-08-11, no PR opened yet).
  **Deadline: 2026-08-18 — 2 days from today. Overdue by the next review.**

## 🟡 INFO

### I-1: `tokens_invalidated_after` included in `UserPublic` API responses (intentional, carry-over)

- **File:** `src/regstack/models/user.py:105–108`
- **Detail:** `UserPublic` includes `tokens_invalidated_after`. The inline
  docstring documents the design intent: SPAs comparing this field to their
  session JWT's `iat` can detect server-side revocation without an extra
  round-trip. The field reveals when the last password/email change occurred —
  low-sensitivity metadata. No action recommended unless future privacy
  requirements tighten.

### I-2: CLI `cmd:` log-source passes operator input to shell (intentional, carry-over)

- **File:** `src/regstack/cli/validate/logtail.py:106`
- **Code:** `argv = ["sh", "-c", target]` where `target` is the
  operator-supplied value after `cmd:`.
- **Detail:** This is an operator-facing tool documented as accepting arbitrary
  shell commands. Runs only on operator workstations under operator credentials.
  No HTTP endpoint reaches this path. Design is intentional. If ever exposed to
  untrusted input, the `cmd:` variant must be removed or sandboxed.

### I-3: PyJWT pinned at exact minimum with no headroom (carry-over)

- **File:** `pyproject.toml` line 55 — `pyjwt>=2.13.0`
- **Detail:** `pyjwt>=2.13.0` is simultaneously the floor and the latest
  upstream release. One new pyjwt advisory would make this floor insufficient
  with no buffer. Monitor weekly; bump floor promptly on any new release.

### §3 — Authentication & Authorization Audit

- Every authenticated endpoint injects `Depends(rs.deps.current_user())` or
  `Depends(rs.deps.current_admin())`. No mutation endpoint accepts unauthenticated
  requests. All API responses go through `UserPublic.from_user()` —
  `hashed_password` and `tokens_invalidated_after` (raw form) excluded from all
  non-admin responses.
- **Bulk-revoke discipline verified:**
  - Password reset (`POST /reset-password`): calls `users.update_password` (bumps
    `tokens_invalidated_after`) then `lockout.clear`.
  - Password change (`POST /change-password`): calls `users.update_password` (same).
  - Email-change confirm (`POST /confirm-email-change`): calls `users.update_email`
    (bumps `tokens_invalidated_after`).
  - Admin disable (`PATCH /admin/users/{id} {is_active: false}`): explicitly calls
    `users.set_tokens_invalidated_after(user.id, rs.clock.now())`.
  - Account deletion: cascades `oauth_identities.delete_by_user_id` then
    `users.delete`; admin delete path follows the same cascade.
- `AuthDependencies._authenticate` five-gate chain verified: scheme check → JWT
  decode (generic 401, reason never echoed) → blacklist lookup → user/`is_active`
  check → `is_payload_bulk_revoked` check.
- OAuth-only users (`hashed_password=None`): same generic 401 on password login
  as wrong-password; `require_password_set()` helper guards `change-password`,
  `change-email`, `delete-account`.
- Constant-time comparison via `pwdlib.PasswordHash` (Argon2id) — never `==`.
- Per-purpose key derivation via `derive_secret(jwt_secret, purpose)` (HMAC-SHA256)
  for all five token purposes (`session`, `password_reset`, `email_change`,
  `phone_setup`, `login_mfa`); compromise of one derived key does not expose others.

### §4 — Storage-layer Injection Safety

**MongoDB backend:** No `$where`, `$expr`, `$function`, or `$accumulator` operators
in any repository. No user-supplied regex patterns — all compiled patterns are
hard-coded. `ObjectId.is_valid()` guards every `get_by_id` and related path
before constructing an ObjectId. No `$in` query accepts an unbounded user-controlled
array.

**SQL backend:** All queries use SQLAlchemy Core with parameterised binds — no
f-string or `%`-style interpolation into raw SQL. Two `text()` calls exist:
`text("SELECT 1")` (health ping, no user input) and
`text("SELECT COUNT(*) FROM users WHERE hashed_password IS NULL")` (migration
pre-check in `0002_oauth.py downgrade()`, no user input). The `UtcDateTime`
TypeDecorator re-attaches UTC tzinfo on read, preventing tz-naive regressions
in the bulk-revoke comparison. All `purge_expired()` implementations use
bound parameters for the cutoff timestamp.

### §6 — Rate Limiting & DoS Prevention

- `LockoutService.check()` called before password verification in `POST /login`;
  `record_failure()` triggered on all four negative branches (user not found,
  wrong password, account disabled, unverified). A locked-out attacker cannot
  probe whether a guess was correct by observing different response codes.
- MongoDB `login_attempts` TTL index configured with
  `expireAfterSeconds=config.login_lockout_window_seconds`. SQL backends expose
  a `purge_expired()` per-repo reaper.
- Admin user listing hard-capped at `limit: Annotated[int, Query(ge=1, le=200)]`
  (default 50). No other paginated endpoint accepts an unbounded limit.
- OAuth state rows: Mongo TTL index on `expires_at`; SQL state rows consumed
  atomically at callback so stale rows cannot accumulate unboundedly.
- No user-facing file upload endpoints exist.

### §7 — Session & Token Security

- HS256 default; `len(raw) < MIN_JWT_SECRET_LENGTH (32)` enforced at
  `JwtCodec.__init__` before any token can be signed.
- `jti` required in decode `options["require"]` list (`["sub", "exp", "iat",
  "jti", "purpose"]`). All encode paths produce `jti=secrets.token_urlsafe(16)`.
- `iat` emitted as float: `"iat": self.iat.timestamp()` in `TokenPayload.to_claims`.
  Microsecond precision preserved. Bulk-revoke comparison `payload.iat <= cutoff`
  is safe — a login completing even microseconds after a password change has
  `iat > cutoff` and is not falsely revoked.
- pyjwt `exp`/`iat` auto-checks disabled (`"verify_exp": False, "verify_iat": False`);
  both re-validated against the injected `Clock` so `FrozenClock`-driven tests
  remain deterministic without monkeypatching `time.time`. Same pattern applied
  consistently in all four custom decode paths (session, email-change, MFA, phone-setup).
- Revocation chain in `_authenticate` confirmed: (1) Bearer scheme → 401;
  (2) JWT decode → generic `"Invalid or expired token."` 401; (3)
  `blacklist.is_revoked(jti)` → 401; (4) `users.get_by_id + is_active` → 401;
  (5) `is_payload_bulk_revoked` → 401.
- No token values appear in any `log.info/debug/warning/error` call. Password
  reset URLs are logged only as `url_without_token` (redacted form).

### §14 — OAuth Subsystem Audit

- **PKCE invariants:** `code_verifier` generated with `secrets.token_urlsafe(64)`
  and stored on the `oauth_states` row. Only the SHA-256 challenge
  (`code_challenge`, B64URL-encoded) goes to the provider in the authorization
  URL — verifier never appears in any redirect or response the browser sees.
- **State row lifecycle:** Missing state row → `?error=bad_state`. Expired row
  compared against `rs.clock.now()` (not `datetime.now(UTC)`) — consistent with
  test isolation via `FrozenClock`. Atomic consume: MongoDB uses
  `find_one_and_delete`; SQL wraps read+delete inside a single `engine.begin()`
  transaction. Second exchange with same id returns 404.
- **ID-token verification:** Signature via `PyJWKClient` + `pyjwt.decode`, `iss`
  matches configured issuer, `aud` matches `client_id`, `exp` validated, `nonce`
  matched. All claims in `require` list. `OAuthIdTokenError` on any failure;
  specific check logged, never echoed to redirect.
- **Linking policy:** Default `auto_link_verified_emails=False`; auto-link fires
  only when enabled AND `info.email_verified=True`. Identity already linked to a
  different user → `?error=identity_in_use`. Same identity already on same
  account → `?error=already_linked`. Both prevent silent ownership transfer.
- **OAuth-only user side effects:** Password login → generic 401 (same as
  wrong-password). `change-password`, `change-email`, `delete-account` guarded
  by `require_password_set()`. `DELETE /oauth/{provider}/link` → HTTP 400 when
  user has no password and only one linked provider.
- **Identity-row uniqueness:** `(provider, subject_id)` and `(user_id, provider)`
  unique at DB level — Mongo unique indexes (`provider_subject_unique`,
  `user_provider_unique`); SQL `UniqueConstraint` on both.
- **Hook events:** `oauth_signin_started`, `oauth_signin_completed`,
  `oauth_account_linked`, `oauth_account_unlinked` all present in `KNOWN_EVENTS`
  and fired at correct points in the router.
