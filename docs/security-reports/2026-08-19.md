## 🟠 WARNING

### W-1 (carry-over, day 9 — DEADLINE MISSED 2026-08-18)

**Section:** §1 — Dependency Vulnerability Check
**CVE:** CVE-2026-69247 — `pkcs7_decrypt` Bleichenbacher oracle
**Affected:** `cryptography` ≥ 48.0.1, < 50.0.0
**Fix:** Bump floor to `cryptography>=50.0.0` in `oauth` and `dev` extras in `pyproject.toml`; run `uv lock`

`pyproject.toml` HEAD (SHA `511527ff`) still declares:
```toml
oauth = ["pyjwt[crypto]>=2.13.0", "cryptography>=48.0.1", "httpx>=0.27"]
...
"cryptography>=48.0.1",   # in dev extra
```

The floor must be `>=50.0.0`. As of `uv.lock`, the resolved version is 49.0.0 — in the vulnerable range.

**Process failure:** Issue #172 (`[security] Raise cryptography floor to >=50.0.0`) was closed on 2026-08-18 by PR #180 — the security review report PR, not a code-fix PR. The fix was never committed. A new tracking issue has been opened.

**regstack's direct exposure:** regstack does not call PKCS7 decrypt. Its use of `cryptography` is limited to JWKS-backed JWT signature verification via `pyjwt[crypto]`. However, `pip install regstack[oauth]` resolves to 49.0.0 by default, shipping a version with an open advisory to all consumers.

**Action required:** `pyproject.toml` one-liner + `uv lock` + document CVE-2026-69247 in the comment block.
