## Section 3 — Authentication & Authorization

### 🟠 W-2 · Email-change token not jti-blacklisted · day 44 (SLA expired +37 d)

Confirmed present (code verified today). `POST /confirm-email-change` (`src/regstack/routers/account.py:177`) decodes the email-change JWT, extracts `user_id` and `new_email`, but never calls `blacklist.is_revoked(jti)` before processing nor `blacklist.revoke(jti, exp)` after success. A valid email-change link can be replayed until its TTL expires (default 1 h).

**Fix:** return `jti` and `exp` from `_decode_email_change_token`, check `await rs.blacklist.is_revoked(jti)` before proceeding, call `await rs.blacklist.revoke(jti, exp)` on success.

### 🟠 W-4 · OAuth new-user concurrent registration race → unhandled 500 · day 44 (SLA expired +37 d)

Unchanged. Concurrent OAuth sign-ins for a new email address can both pass the `find_by_subject` check, both attempt `users.create`, and one raises an unhandled `UserAlreadyExistsError`. The callback redirects to `?error=oauth_error` (generic 500 path) instead of the expected `?error=email_in_use` or a clean session token for the winner. Catching `UserAlreadyExistsError` in `_resolve_user` and re-trying with `find_by_subject` would close the window.

### 🟠 W-8 · Timing oracle on login for OAuth-only accounts · day 26 (SLA expired +19 d)

Confirmed present (code verified today). `hashed_password is None` short-circuits `pwdlib`'s `verify()` call via `or`-short-circuit evaluation (`src/regstack/routers/login.py:99`): `if user.hashed_password is None or not rs.password_hasher.verify(payload.password, user.hashed_password)`. When `hashed_password is None`, the Argon2 `verify()` call is skipped entirely, making the 401 measurably faster than a wrong-password 401 for a password-having account.

**Fix:** when `hashed_password is None`, call `rs.password_hasher.verify(payload.password, <sentinel_hash>)` before returning the 401 to normalise timing.

### 🟠 W-13 · Admin `promote-pending` echoes unvalidated email path param · day 11 (SLA expired +3 d)

Confirmed present (code verified today). `src/regstack/routers/admin.py` declares `email: str = Path(...)` instead of `email: EmailStr = Path(...)` on the `admin_promote_pending` endpoint. A malformed value passes through without validation and is echoed unescaped in the 404 body (`f"No pending registration for {email}."`) and the 409 body (`f"A user with email {email} already exists."`). Endpoint requires `current_admin()` so attack surface is admin users only.

**Fix (1 line):** change `email: str = Path(...)` → `email: EmailStr = Path(...)`.

## Section 14 — OAuth Subsystem Audit

### 🟠 W-6 · SQL `OAuthStateRepo.consume` non-atomic under READ COMMITTED · day 36 (SLA expired +29 d)

Unchanged. `src/regstack/backends/sql/repositories/oauth_state_repo.py:63` wraps SELECT + DELETE in `engine.begin()` (one transaction), but PostgreSQL's default READ COMMITTED isolation means a concurrent request can read the same row between the SELECT and DELETE, allowing two `/oauth/exchange` calls with the same state ID to both return a session token. Mongo is safe (`find_one_and_delete` is atomic). SQL fix requires `SELECT … FOR UPDATE` on the SELECT or a `DELETE … RETURNING` for true atomicity.

### 🟠 W-10 · `GoogleProvider` client_secret in plain string at construction · day 26 (SLA expired +19 d)

Unchanged. `src/regstack/app.py:188` calls `GoogleProvider(client_secret=oauth_cfg.google_client_secret.get_secret_value(), ...)`, extracting the `SecretStr` into a plain `str` that lives for the lifetime of the `RegStack` instance. `GoogleProvider.__init__` stores it as `self._client_secret: str`. Not a code-level exposure but `SecretStr` wrapping in `GoogleProvider` would prevent accidental inclusion in `repr()` / stack traces.

### 🟡 I-8 · `mfa_confirm` does not re-check `is_verified` · day 11

Carry-forward. `POST /login/mfa-confirm` and `POST /phone/confirm` do not re-check `user.is_verified`. Not currently exploitable, but defence-in-depth recommendation.

### 🟢 CLEAN (flow integrity)

PKCE: `code_verifier` stored on `oauth_states` row only; only `code_challenge` sent to provider. State row lifecycle: missing row → `?error=bad_state`; expired row → `?error=state_expired` using `rs.clock.now()`. Mongo consume: `find_one_and_delete` (atomic).
